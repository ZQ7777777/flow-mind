# business-base 发起页附件模板列表设计

## 1. 背景

`business-base` 流程发起页的“影像资料上传”区域左侧当前按用户已经选择的具体文件生成档案列表。未上传文件时，流程定义中已经配置的附件要求不会出现在列表中，列表展示的信息也偏向文件实例，而不是流程定义的附件模板。

流程启动上下文已经返回申请节点适用的附件规则，包含附件名称、允许扩展名、单文件大小限制、必填标记、数量限制和排序信息。本次改造使用这些规则作为档案列表的行源。

## 2. 目标

将发起页档案列表改为“每个附件模板一行”，并展示：

- 档案（附件）名称
- 档案（附件）格式
- 大小限制
- 是否必填
- 下载
- 是否上传

已上传文件挂在对应模板行的下载单元格中。一个模板存在多个文件时仍只显示一行，并提供多个下载项；未上传时显示“未上传”和“暂无下载”。

## 3. 非目标

- 不增加附件模板空白样例文件。
- 不修改流程启动上下文接口和后端附件 DTO。
- 不改变附件上传、提交校验、文件预览、文件删除或启动提交协议。
- 不把尚未提交的浏览器本地文件持久化到后端。

## 4. 设计

### 4.1 数据来源

`orderedAttachments` 继续作为流程附件规则的排序后数据源。新增一个仅用于列表展示的计算值 `attachmentTemplateRows`：

1. 遍历 `orderedAttachments`，保证每个模板始终生成一行。
2. 按 `attachmentCode` 关联现有 `attachmentRows` 中的本地文件行。
3. 将关联文件用于下载链接和“是否上传”状态，不复制上传和预览状态。

现有 `attachmentRows` 继续负责实际文件的预览选择、文件格式识别、ObjectURL 生命周期和删除后的选中状态清理。

### 4.2 列表展示

列表列顺序为：

1. 序号
2. 档案（附件）名称
3. 档案（附件）格式
4. 大小限制
5. 是否必填
6. 下载
7. 是否上传

展示规则：

- 格式：将 `allowedExtensions` 规范化后以大写扩展名展示，多个格式使用中文顿号分隔；为空显示“不限制”。
- 大小限制：使用现有文件大小格式化工具展示 `maxSizeBytes`，未配置时显示“不限制”。限制语义为单个文件大小。
- 是否必填：`required` 为真显示“是”，否则显示“否”。
- 下载：每个已上传文件显示一个以文件名为文本的本地下载链接；未上传显示“暂无下载”。
- 是否上传：关联文件数量大于零显示“已上传”，否则显示“未上传”。

模板行点击行为：

- 模板有文件时，选中该模板的第一个文件并沿用现有预览面板。
- 模板没有文件时，不改变当前预览选中项。
- 点击下载链接时阻止行点击，避免下载操作改变预览选中项。

### 4.3 状态与生命周期

- 上传文件后，模板行数量不变，只更新下载项和上传状态。
- 删除模板的最后一个文件后，模板行保留，下载恢复为“暂无下载”，状态恢复为“未上传”，现有预览清空逻辑继续生效。
- 新增的模板行和文件链接使用稳定的模板编码、文件行 ID 或文件索引作为 Vue key，避免同名文件造成渲染冲突。
- ObjectURL 仍只由现有 `objectUrlFor` 创建，并由现有监听和卸载逻辑回收。

### 4.4 空值和无模板场景

- 没有附件模板时继续显示“暂无影像资料上传要求”。
- `allowedExtensions` 为空时上传控件不增加格式限制，列表显示“不限制”。
- `maxSizeBytes` 为空时列表显示“不限制”，现有上传校验规则保持不变。

## 5. 测试设计

在 `WorkflowStartShell.spec.ts` 增加或调整以下行为测试：

1. 未上传时仍渲染每个附件模板行，并显示名称、格式、大小限制、必填状态、“暂无下载”和“未上传”。
2. 上传一个文件后，模板列表仍只有一行，显示文件下载链接和“已上传”。
3. 同一模板上传多个文件后，单行中显示多个下载链接。
4. 删除最后一个文件后，模板行保留并恢复为“暂无下载”和“未上传”，预览内容清空。
5. 没有格式或大小限制时显示“不限制”。
6. 现有必填附件校验和通用启动提交行为继续通过。

验证命令：

- `npm test -- --run`
- `npm run typecheck`
- `npm run build`

工作目录为 `business-base/frontend`。

## 6. 验收标准

- 档案列表始终按流程定义附件模板一行展示，而不是按已上传文件生成行。
- 列表完整显示名称、格式、大小限制、必填、下载和上传状态。
- 多文件下载项全部可用，未上传模板无虚假下载链接。
- 右侧上传、预览、删除和最终提交行为不回归。
- 前端测试、类型检查和构建通过。
