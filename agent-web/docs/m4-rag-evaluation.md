# M4 本地 RAG 实现与离线验收

## 边界

M4 使用 SQLite 保存冻结样例，不接入外部向量库、embedding 服务或真实模型。`agent-web/evals/**`、生成答案、golden code 和 repair 输出不进入语料库。

## 准入与不可变性

语料晋级为显式操作，且失败关闭。来源 generation 必须同时满足：当前 revision 的技术硬门禁全部通过；调用方提交至少一个全部为 `PASSED` 的业务断言；文件已经人工确认写入且 generation 完成。晋级时从目标目录读取 Manifest 文件、复核批准时的 SHA-256，并把原文及 hash 冻结保存。缺少任意一类证据、源文件变化或文件缺失都会拒绝晋级。

## 检索协议

检索先按 `projectId + contractVersion + capabilities` 完成元数据过滤，之后才对候选原文进行本地 BM25 排序。中文使用二元字切分，英文及标识符使用小写词元。搜索响应只含 `key、summary、version、sha256、score、capabilities`；原文只能凭同一次检索返回的 key 读取，且读取前再次校验 hash。

SQLite 审计分别保存 query、过滤条件、候选 key、结果 key，以及最终读取的 key、hash 和时间。未由指定 retrieval 返回的 key 无法读取。

## 离线代理 A/B

预先声明的失败类别是“生成任务无法获得版本和业务能力兼容的已审核上下文”。对冻结 V1 任务集中的 25 个可生成任务运行离线检索：

| 路径 | 上下文可用任务 | 真实模型调用 | 费用 |
| --- | ---: | ---: | ---: |
| 无 RAG | 0/25 | 0 | 0 |
| 元数据过滤 + BM25 | 18/25 | 0 | 0 |

另外 5 个应被需求门禁阻断的任务不执行检索。确定性生成和关键业务断言沿用 M2 的 30/30 离线结果，没有因 RAG 接入而降低。该指标仅证明检索层覆盖改善，不代表真实代码生成成功率；同模型、同 Prompt 的真实成对 A/B 因费用约束标记为 `NOT_MEASURED`。

剩余 7/25 是稳定的词法漏召回信号。M5 可以在同一个 Retriever 边界后评估本地 embedding/混合排序，但只有在不降低版本过滤、hash 冻结和审计能力的前提下才应启用。
