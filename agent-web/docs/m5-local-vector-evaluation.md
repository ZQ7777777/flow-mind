# M5 本地向量增强与离线验收

## 启用依据

M4 在冻结任务集的 25 个可生成任务上稳定召回 18 个任务，剩余 7 个任务因查询和已审核样例缺少共同词面而无法被 BM25 召回。该结果满足 M5 “先证明词法漏召回，再启用本地向量增强”的前置条件。

## 实现

M5 保持 M4 的检索边界：`projectId、contractVersion、capabilities` 元数据过滤必须先完成，只有过滤后的冻结文档才能进入排序。排序新增以下本地组件：

- embedding：`LOCAL_SEMANTIC_HASH_V1`，256 维，结合业务领域概念、标识符、中文二元字和能力标签；
- chunker：`CODEPOINT_800_OVERLAP_100_V1`，按 Unicode code point 切分 800 字符、重叠 100 字符；
- index：`LOCAL_RAG_INDEX_V1`，向量、版本和被索引原文 SHA-256 随冻结文档存入 SQLite；旧 M4 文档在首次合格混合检索时确定性补建；
- retriever：`HYBRID_RRF_V1`，对 BM25 与余弦相似度结果执行 reciprocal-rank fusion。

每次检索响应和 SQLite 审计均保存 retriever、tokenizer、embedding、维度、chunker、index 版本以及各结果的词法、向量和融合分数。按 key 读取、hash 校验和读取审计保持不变。

该 embedding 是本地确定性领域特征嵌入，不冒充通用神经语义模型。它不下载权重、不访问网络，也不向新增接收方发送查询或代码。

## M4/M5 离线对比

测试沿用冻结 V1 任务查询和一个非评测来源的已审核通用样例；评测任务、断言、golden code 和生成答案均未进入语料。

| 检索器 | 已审核上下文可用任务 | 增量 | 外部调用 |
| --- | ---: | ---: | ---: |
| `BM25_V1` | 18/25 | 基线 | 0 |
| `HYBRID_RRF_V1` | 25/25 | +7 | 0 |

另外 5 个需求应阻断任务不会进入检索。M2 确定性生成的 30/30 技术与关键业务门禁继续通过，因此此次覆盖提升没有以降低关键断言为代价。

该对比证明的是检索覆盖的可重复边际收益，不等同于真实模型代码生成成功率。根据费用限制，真实同模型/Prompt A/B 继续标记为 `NOT_MEASURED`，模型调用数及费用为 0。
