# 实习生 C：M1 表单字段与附件模板执行计划

## 1. 阶段目标

M1 的目标是把 M0 已冻结的 C 线契约推进到可用的定义期能力：流程定义详情不仅能返回节点和连线，还能返回表单字段、全局附件模板版本和流程定义附件配置。完成后，A 线的定义保存、查询、复制、删除、发布和激活动作可以同时处理 C 的扩展数据；B 线可以读取包含表单和附件配置的完整定义快照。

本阶段只实现“字段定义和附件要求”，不实现运行期实际表单值、实际文件上传、附件元数据、文件存储、下载、删除或任务办理时的必填附件拦截。

## 2. 当前基线

已有内容：

- SQLite 初始化脚本已包含 `process_form_field`、`process_attachment_template`、`process_definition_attachment_config`。
- 持久化实体已存在：`ProcessFormFieldEntity`、`ProcessAttachmentTemplateEntity`、`ProcessDefinitionAttachmentConfigEntity`。
- API DTO 已存在：`ProcessFormFieldDTO`、`ProcessAttachmentConfigDTO`、`ProcessAttachmentTemplateDTO`。
- `SaveProcessGraphRequest` 已预留 `formFields` 和 `attachmentConfigs`。
- `ProcessDefinitionDetailDTO` 已预留表单字段和附件模板配置返回字段。
- M0 已完成 SPI、Service、事件和幂等并发契约基线。

尚缺内容：

- 三类 M1 表的 Repository。
- 表单字段、附件模板和定义附件配置的保存、查询、复制、删除、激活和校验。
- 与 A 线定义生命周期的同事务接入。
- 与 B 线完整定义读取和缓存失效的协作接口。
- M1 级别 Repository、校验器和跨线集成测试。

## 3. 职责边界

C 在 M1 负责：

1. 表单字段定义的持久化、校验、查询、复制和删除。
2. 全局附件模板的版本化管理、启停和引用保护。
3. 流程定义附件配置组的草稿保存、查询、复制、删除和激活。
4. 为 A 的 `saveGraph`、`getDefinition`、`copyDefinition`、`deleteDefinition`、`validateForPublish`、`publish` 和 `activate` 提供扩展数据能力。
5. 为 B 的运行时定义快照提供完整扩展配置读取入口。
6. 提供事务提交后的定义缓存失效协作点。

C 在 M1 不负责：

- 用户实际填写的表单值。
- `process_attachment` 运行期附件元数据。
- 文件内容保存、读取和删除。
- `FileStorageProvider` 调用。
- 附件上传、下载、授权和软删除。
- 任务办理时校验附件是否已上传。
- 任何具体业务判断，例如入金、报销或请假规则硬编码。

## 4. 微任务拆分

### C1.1 契约与数据语义整理

目标：

- 明确 `ProcessAttachmentConfigDTO` 用于保存定义附件配置。
- 明确 `ProcessAttachmentTemplateDTO` 用于查询详情时合并展示“附件模板版本 + 定义附件配置”。
- 统一 `allowed_extensions` 存储格式为 JSON 数组，对外 DTO 使用 `List<String>`。
- 新增或确认模板状态 `ENABLED/DISABLED`、配置状态 `DRAFT/ACTIVE/INACTIVE` 的使用边界。
- M1 新增公开 API 类型遵守 M0 JavaBean 约定，可以使用Lombok 。

交付：

- M1 契约说明补充到技术实现说明或本阶段完成记录。
- DTO 字段语义不再冲突。

### C1.2 Repository 层落地

目标：

- 新增 `ProcessFormFieldRepository`。
- 新增 `ProcessAttachmentTemplateRepository`。
- 新增 `ProcessDefinitionAttachmentConfigRepository`。

能力要求：

- 表单字段：按定义替换保存、按定义查询、复制到新定义、删除。
- 附件模板：创建新版本、按编码查最大版本、按 ID 查询、启停、判断是否被生效配置引用。
- 附件配置：保存草稿配置组、查询定义配置、查询激活配置组、复制、删除草稿、激活配置组并下线旧激活组。

交付：

- Repository 实现和 SQLite 集成测试。
- 不在 Controller 或 Starter 中直接访问 Repository。

### C1.3 表单字段能力

目标：

- 实现表单字段保存、查询、复制和删除。
- 校验字段编码、名称、类型、控件类型、必填标志、排序和 `validationRule` JSON。
- 同一定义内 `fieldCode` 唯一。

验收：

- 合法字段可随定义保存并按 `sortOrder, fieldCode` 稳定返回。
- 重复字段编码失败。
- 非法 JSON 失败。
- 复制定义时生成新主键并绑定目标 `definitionId`。

### C1.4 附件模板版本化能力

目标：

- 创建附件模板时按 `attachmentCode` 自动递增 `templateVersion`。
- `allowedExtensions` 统一小写、去掉前导点、去重后按 JSON 数组保存。
- `maxSizeBytes` 必须大于 0。
- 已被 ACTIVE 配置引用的模板版本不可原地修改格式和大小；规则变化必须新建版本。
- 禁用模板只阻止新配置引用，不影响历史已绑定配置。

验收：

- 同一附件编码多次创建时版本递增。
- 禁用模板后不能被新的定义附件配置引用。
- 被激活配置引用的模板版本不能破坏性修改。

### C1.5 流程定义附件配置组能力

目标：

- 保存定义附件配置草稿组。
- 校验模板存在且启用。
- 校验 `required=true` 时 `minCount >= 1`。
- 校验 `maxCount >= minCount`。
- 校验 `applicableNodeCodes` 引用当前定义真实节点。
- 同一配置组内 `attachmentCode` 和 `attachmentTemplateId` 不重复。
- 同一定义同一时刻只允许一个 ACTIVE 配置组。

验收：

- 草稿配置可保存和查询。
- 激活新配置组时旧 ACTIVE 变为 INACTIVE。
- 未知节点、禁用模板、重复绑定和非法数量规则均失败。

### C1.8 测试、文档和阶段收口

目标：

- 补齐 M1 技术实现说明和测试文档。
- 补齐入金申请样例测试数据：申请人、金额、账号、银行回单模板。
- 执行模块测试和根测试。

建议命令：

```powershell
mvn -q -pl platform/platform-core -am test
mvn -q test
```

验收：

- M1 所有 Repository、校验器和跨线集成测试通过。
- 文档记录已完成微任务、测试命令和结果。
- 不夹带 M2 及以后运行期能力。

## 5. A/B 协作依赖

| 依赖方 | C 需要的最小能力 | C 的处理方式 |
| --- | --- | --- |
| A | 定义、节点、连线正式持久化和读取；定义状态；`saveGraph/getDefinition/copy/delete/validate/publish/activate` 实现或挂点 | C 提供扩展生命周期组件，由 A 在同事务内调用 |
| B | 完整定义读取端口和缓存失效调用点 | C 提供表单和附件配置读取，不复制 B 的运行时快照类型 |

并行策略：

- C1.2 到 C1.5 可先基于现有 DDL、实体和 DTO 独立推进。
- C1.6 等 A 的定义生命周期实现或挂点稳定后接入。
- C1.7 等 B 的读取端口和缓存失效接口稳定后接入。
- A/B 未就绪时，只在测试目录使用夹具，不在生产代码创建临时公共替代类型。

## 8. M1 完成标准

- 表单字段、附件模板和定义附件配置具备生产级 Repository 与校验器。
- 流程定义保存、查询、复制、删除、发布校验和激活可以处理 C 扩展数据。
- `ProcessDefinitionDetailDTO` 能完整返回节点、连线、表单字段和附件配置。
- 附件模板支持版本化和启停，已生效引用不被破坏。
- 同一定义同时只有一个 ACTIVE 附件配置组。
- B 线可以读取完整定义扩展配置，配置变更后能触发缓存失效。
- M1 不包含实际附件上传、下载、文件存储或运行期必填附件校验。
- `mvn -q -pl platform/platform-core -am test` 和根目录 `mvn -q test` 通过。
