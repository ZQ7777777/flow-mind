# 实习生 C：M1 C1.1 契约说明

## 1. 本节边界

C1.1 只冻结 M1 定义期扩展契约和字段语义，不修改运行期附件能力，不保存用户实际表单值，不调用 `FileStorageProvider`，不实现附件上传、下载、删除或运行期必填附件校验。

## 2. DTO 职责

| DTO | 职责 |
| --- | --- |
| `ProcessFormFieldDTO` | 表达流程定义下的表单字段结构，包括字段编码、名称、数据类型、控件类型、必填标志、校验规则、默认值和排序。 |
| `ProcessAttachmentConfigDTO` | 用于保存流程定义附件配置输入，表达配置组内每一项引用哪个全局附件模板版本，以及必填、数量、适用节点和排序要求。 |
| `ProcessAttachmentTemplateDTO` | 用于定义详情查询的合并展示，包含全局附件模板版本信息和流程定义附件配置项信息。 |

`SaveProcessGraphRequest.formFields` 使用 `ProcessFormFieldDTO` 承载定义期表单字段。`SaveProcessGraphRequest.attachmentConfigs` 使用 `ProcessAttachmentConfigDTO` 承载定义期附件配置。`ProcessDefinitionDetailDTO.attachmentTemplates` 返回 `ProcessAttachmentTemplateDTO`，表示“模板版本 + 定义配置”的合并视图。

## 3. 字段存储语义

| 表 | Entity | DTO | 说明 |
| --- | --- | --- | --- |
| `process_form_field` | `ProcessFormFieldEntity` | `ProcessFormFieldDTO` | 表单字段定义，只描述字段结构，不保存用户填写值。 |
| `process_attachment_template` | `ProcessAttachmentTemplateEntity` | `ProcessAttachmentTemplateDTO` 的模板字段 | 全局附件模板版本，按 `attachment_code + template_version` 唯一。 |
| `process_definition_attachment_config` | `ProcessDefinitionAttachmentConfigEntity` | `ProcessAttachmentConfigDTO` 和 `ProcessAttachmentTemplateDTO` 的配置字段 | 流程定义附件配置项，多条记录通过 `attachment_config_id` 组成一个配置组。 |

`allowed_extensions` 统一按 JSON 数组字符串落库，例如 `["pdf","jpg","png"]`；对外 DTO 使用 `List<String>`。Repository 层只透传数据库字符串，扩展名规范化、JSON 校验和 DTO 转换在后续服务/校验层完成。

`applicable_node_codes` 统一按 JSON 数组字符串落库，例如 `["apply"]`；对外 DTO 使用 `List<String>`。节点存在性校验不属于 C1.2 Repository 层。

## 4. 状态语义

`AttachmentTemplateStatusEnum` 只包含：

- `ENABLED`：模板版本可被新的定义附件配置引用。
- `DISABLED`：模板版本停用，后续服务层应阻止新配置引用；历史已绑定配置不被破坏。

`AttachmentConfigStatusEnum` 只包含：

- `DRAFT`：草稿配置组，同一定义下不限制数量；保存草稿时只替换指定 `attachment_config_id` 对应的草稿组。
- `ACTIVE`：当前生效配置组，同一定义同一时刻只允许一个生效配置组。
- `INACTIVE`：已下线配置组，作为历史绑定保留。

## 5. C1.2 Repository 约束

Repository 只负责 SQLite 表访问和 Entity 映射：

- 不访问 Controller 或 Starter。
- 不实现流程定义 CRUD。
- 不实现运行期附件元数据。
- 不调用文件存储 SPI。
- 不做 A/B 生命周期编排。
- 不做字段和附件配置的完整业务校验。

C1.2 新增的 Repository 方法只提供保存、查询、复制、删除、启停和激活所需的最小数据库能力，供后续 C1.3-C1.7 服务层和生命周期接入复用。
