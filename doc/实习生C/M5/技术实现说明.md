# 实习生 C：M5 技术实现说明

## 1. 实现范围

M5 在既有 M0-M4 基线和 B 线 M5 增强动作之上，补齐 C 线负责的认领/取消认领、委托认领、审计、已阅、提醒、告警、超时扫描、REST 和 Starter 装配能力。不新增第二套 `ProcessRuntimeService`、`TaskQueryService` 或 `AdminProcessService`，所有公开入口继续复用既有 Service 契约。

本阶段不重复实现 B 线的 `reject/returnToStarter/withdraw/directSend/transfer/addSign`，也不引入真实短信、邮件、企业微信或 HTTP 回调实现。消息发送仍通过宿主可替换的 `MessagePublisher` SPI。

## 2. 认领与取消认领

`DefaultProcessRuntimeService.claim/unclaim` 已从阶段占位改为委托 `TaskClaimCoordinator`：

- `claim` 复用 `RuntimeRequestValidator` 校验可信操作者，使用 `RuntimeOperationExecutor` 写入 `CLAIM` 幂等记录。
- `claim` 只允许 `ACTIVE` 任务，校验 `expectedTaskVersion` 后调用 `ActiveTaskRepository.claim(...)` 做 CAS 更新。
- 候选人校验支持本人候选人，也支持通过 `DelegateProvider.findPrincipals(operatorUserId, now)` 获取的委托人候选任务。
- `unclaim` 只允许当前实际认领人取消认领，调用 `ActiveTaskRepository.unclaim(...)` 做 CAS 更新。
- 成功后写 `process_history_task` 控制轨迹、`process_audit_log` 审计、发布 `TASK_CLAIMED/TASK_UNCLAIMED` 回调，并返回最新 `updatedTasks.taskVersion`。

这里的“委托协调器”指内部编排组件，不是新的公开 Service。它集中处理认领动作所需的校验、幂等、事务、CAS、历史、审计和回调，避免把 `DefaultProcessRuntimeService` 继续堆大，同时保持外部入口不变。

## 3. 已阅记录

新增 `ReadRecordManager` 和 `ProcessReadRecordRepository`：

- `POST /api/platform/instances/{instanceId}/read` 显式标记已阅，当前用户来自 `CurrentUserProvider`。
- `process_read_record` 使用 `instance_id + user_id` 幂等 upsert，重复阅读只刷新 `read_at`。
- `TaskQueryService.queryReadRecords` 委托 `ReadRecordManager.query(...)`，支持按实例、用户分页查询。

## 4. 统一审计

新增 `AuditLogWriter`、`AuditLogCommand`、`DefaultAuditLogWriter` 和 `ProcessAuditLogRepository`：

- 新增 M5 动作统一写 `process_audit_log`。
- `DefaultAdminProcessService.queryAuditLogs` 改为读取 `ProcessAuditLogRepository`。
- 审计查询支持目标类型、目标 ID、实例 ID、操作者和分页。

## 5. 提醒、告警与超时扫描

新增 `DefaultProcessMonitorService`，实现 `ProcessMonitorService`：

- `remindTask`：先查询幂等记录，校验任务处于 `ACTIVE/CLAIMED`，写 `process_reminder_record(PENDING)`，写审计，事务后调用 `MessagePublisher.publish`，成功改 `SENT`，失败改 `FAILED`。
- `queryReminders`：支持实例、任务、提醒类型、提醒状态、创建时间分页过滤。
- `scanTimeoutTasks`：扫描 `due_at <= scanAt` 且状态为 `ACTIVE/CLAIMED` 的任务；`dryRun=true` 只返回任务；`dryRun=false` 为每个任务生成一条打开中的 `TASK_TIMEOUT` 告警，并通过 `taskId + alertType + OPEN` 防重复。
- `queryAlerts`：支持实例、任务、告警类型、级别、状态、创建时间分页过滤。
- `handleAlert`：只允许 `OPEN -> HANDLED/IGNORED`，写处理人、处理时间、审计和幂等成功结果。

M5 只实现可验收的最小超时闭环，复杂节点级策略、升级策略和批量调度仍留到 M6。

## 6. REST 与 Starter 装配

REST 新增或补齐：

- `POST /api/platform/instances/{instanceId}/read`
- `GET /api/platform/instances/{instanceId}/read-records`
- `POST /api/platform/tasks/{taskId}/remind`
- `GET /api/platform/reminders`
- `POST /api/platform/admin/timeout-scan`
- `GET /api/platform/admin/alerts`
- `POST /api/platform/admin/alerts/{alertId}/handle`
- `GET /api/platform/admin/audit-logs`

`PlatformAutoConfiguration` 装配了 M5 新增 Repository、`AuditLogWriter`、`ReadRecordManager`、`DefaultProcessMonitorService`、查询组件和默认 Mock SPI，并通过 `@ConditionalOnMissingBean` 保持宿主覆盖能力。

## 7. 关键测试

新增或补充的 M5 测试包括：

- `TaskClaimCoordinatorTest`：覆盖委托候选人认领、非候选非委托拒绝。
- `DefaultProcessMonitorServiceTest`：覆盖超时扫描 dryRun 不写告警、非 dryRun 写告警且防重复。
- `M5MonitorRepositoryIntegrationTest`：覆盖已阅 upsert、审计、提醒、告警状态流转和新增过滤条件。

根级 `mvn -q test` 已通过。
