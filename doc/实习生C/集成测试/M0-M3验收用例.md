# M0-M3 跨阶段端到端验收用例

## 1. 文档目的

本文档只描述 M0-M3 的端到端集成测试，不再罗列单元测试、Repository 测试、契约测试或单组件测试。

端到端测试以“入金申请”为统一业务场景，从流程定义开始，经过发布激活、实例启动、申请提交、经理审批、财务审批、查询、终止或删除，验证实习生 A、B、C 实现的组件能够在同一个 Spring Boot 上下文和同一个 SQLite 数据库中协同工作。

本轮忽略灰度发布，不把灰度启用、灰度命中或灰度停用作为验收内容。

## 2. 测试范围

端到端链路包括：

1. 流程定义创建、流程图保存、表单字段和附件配置保存；
2. 定义校验、发布、激活和版本选择；
3. 流程实例启动、申请提交、经理审批和财务审批；
4. 幂等重放、并发审批和事务回滚；
5. 实例详情、活动任务、历史任务、审批意见和我发起查询；
6. 回调 Outbox、操作记录和数据库状态一致性；
7. 实例终止和实例删除；
8. Core、查询 Service、REST 和 Starter 入口一致性。

不属于本轮端到端验收范围：

- 单个 DTO、枚举、Validator 或 Repository 的独立行为；
- M4-M6 的真实文件存储、已阅、提醒、告警和增强审批动作；
- 灰度发布。

## 3. 公共测试环境

| 项目 | 约定 |
| --- | --- |
| Java | Java 8 |
| 测试框架 | Spring Boot Test + JUnit 5 |
| 数据库 | 仓库根目录 `identifier.sqlite` |
| 测试流程编码 | `it-deposit` |
| 测试操作号 | `e2e-*` |
| 发起人 | `starter` |
| 经理审批人 | `manager` |
| 财务审批人 | `finance` |
| 定义操作人 | `operator` |

测试只允许清理 `it-deposit` 流程及 `e2e-*` 操作产生的数据，不得清理数据库中的其他业务数据。

## 4. 标准入金流程

V1 标准流程：

```text
开始 → 入金申请 → 经理审批 → 财务审批 → 结束
```

定义数据至少包括：

- 表单字段：`amount`；
- 必传附件配置：`e2e-receipt`；
- 发起变量：入金金额；
- 提交变量：账户名称；
- 申请、经理审批和财务审批意见。

## 5. 端到端验收用例

### E2E-001 入金申请主流程

| 项目 | 内容 |
| --- | --- |
| 覆盖阶段 | M0 Schema/事务基础；M1 定义；M2 运行时；M3 查询 |
| 前置条件 | `identifier.sqlite` 可连接，不存在本轮残留的 `it-deposit` 数据 |
| 操作步骤 | 创建定义；保存流程图、字段和附件配置；发布激活；启动实例；提交申请；经理审批；财务审批；查询实例详情 |
| 预期结果 | 实例为 `COMPLETED`；版本为 V1；无开放任务；产生 3 条业务历史和 3 条意见；变量完整；回调和操作记录与四次运行时动作一致 |
| 自动化方法 | `e2e001MainFlowCompletesFromDefinitionToRuntimeAndQuery` |
| 通过级别 | 必须通过 |

### E2E-002 全链路幂等重放

### E2E-003 经理审批并发

| 项目 | 内容 |
| --- | --- |
| 覆盖阶段 | M0 CAS；M2 运行时并发 |
| 前置条件 | 实例已提交到经理审批节点 |
| 操作步骤 | 两个线程使用不同操作号、相同任务版本同时审批经理任务 |
| 预期结果 | 仅一个请求成功；经理历史只有一条；财务活动任务只有一条；回调不重复；失败请求返回并发冲突 |
| 自动化方法 | `e2e003ConcurrentManagerApprovalCreatesOneFinanceTask` |
| 通过级别 | 必须通过 |

### E2E-004 任务动作事务回滚

| 项目 | 内容 |
| --- | --- |
| 覆盖阶段 | M0 事务；M2 运行时、历史和回调 |
| 操作步骤 | 在任务 CAS 之后分别模拟历史归档失败、后继任务创建失败和回调 Outbox 写入后失败 |
| 预期结果 | 当前任务状态、历史、后继任务和回调同时回滚；失败操作有明确状态；使用新操作号可重新执行成功 |
| 当前自动化 | 跨阶段测试自动覆盖经理审批的回调失败和重试；事务专项覆盖历史、后继任务和回调三类故障 |
| 补充要求 | 如正式验收要求 9 份独立证据，应参数化申请、经理、财务三个步骤与三类故障点 |
| 通过级别 | 必须通过 |

### E2E-005 V1/V2 版本治理

| 项目 | 内容 |
| --- | --- |
| 覆盖阶段 | M1 定义版本；M2 运行实例版本冻结；M3 查询 |
| 操作步骤 | 激活 V1 并启动实例 A；创建、发布并激活 V2；再启动实例 B；继续推进实例 A |
| 预期结果 | A 始终绑定 V1；B 使用 V2；激活 V2 后的新实例不再选择 V1；V2 上线不改变 A 的定义 ID 和版本 |
| 自动化方法 | `e2e005RunningInstanceKeepsV1WhileNewInstanceUsesV2` |
| 说明 | 当前 V1、V2 的流程结构相同，主要验证版本选择和实例冻结 |
| 通过级别 | 必须通过 |

### E2E-006 运行中实例终止

| 项目 | 内容 |
| --- | --- |
| 覆盖阶段 | M2 运行时；M3 实例管理 |
| 前置条件 | 入金实例处于经理或财务审批节点，并存在开放任务 |
| 操作步骤 | 使用新操作号终止实例；查询实例、活动任务、历史、审计、回调和操作记录；再次重放终止请求 |
| 预期结果 | 实例为 `TERMINATED`；所有开放任务和活动任务组被取消；取消任务写入历史；产生审计和 `PROCESS_TERMINATED` 回调；重放不增加任何业务记录 |
| 当前自动化 | `M0M3CrossStageSpringBootIntegrationTest.e2e006TerminateRunningInstanceCommitsReplaysAndRollsBackAtomically` 已从真实定义创建、发布激活、启动和提交开始，覆盖终止成功、重放及回调失败全回滚 |
| 通过级别 | 必须通过 |

### E2E-007 实例删除

| 项目 | 内容 |
| --- | --- |
| 覆盖阶段 | M3 实例管理和数据治理 |

| 通过级别 | 必须通过 |

## 6. 执行顺序

建议按以下顺序执行：

1. E2E-001 主流程；
2. E2E-002 幂等；
3. E2E-003 并发；
4. E2E-004 事务；
5. E2E-005 版本治理；
6. E2E-006 实例终止；
7. E2E-007 实例删除；
8. 平台全量回归。

## 7. 验收门禁

- E2E-001、E2E-002、E2E-003、E2E-004、E2E-005、E2E-006、E2E-007 任一失败，Core 端到端验收不得通过。
- 自动化执行必须为 0 Failure、0 Error。
- 不得使用 Mock Repository 或内存集合代替 SQLite。
- 外部用户目录、附件文件存储和委托关系允许使用测试替身，但必须在结果文档中说明。
- 测试不得删除 `identifier.sqlite` 中非 `it-deposit`、非 `e2e-*` 的业务数据。
