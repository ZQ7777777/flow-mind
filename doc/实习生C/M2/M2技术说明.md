# 实习生 C：M2 运行期外围能力技术说明

## 1. 本次实现范围

本次按 M2 执行计划和 vibe-coding 计划落地 C 线运行期外围能力：

- 操作幂等：复用并扩展 `OperationIdempotencyService` 和 `ProcessOperationRecordRepository`。
- 运行状态校验：新增只读 `RuntimeStateValidator`，供 B 线在任务 CAS 前调用。
- 审批意见与流程轨迹：新增历史任务 Repository、归档 Writer 和查询 Service。
- 回调日志 Outbox：新增回调日志 Repository、Outbox 写入、事件工厂、默认回调服务。
- 测试：补充真实 SQLite 表约束下的幂等、状态校验、历史查询、回调 outbox 测试。

本次没有实现：

- B 线主状态机：不创建下一节点任务，不判断流程办结，不硬编码串行流转。
- 审计日志写入和查询：保留到 M5。
- 实例级附件保存、下载、删除、必填校验：保留到 M4。
- 真实 HTTP 回调投递：M2 只提供 `WorkflowCallbackHandler` SPI 调用和状态记录。

## 3. 数据库操作

### process_operation_record

实现位置：

- `ProcessOperationRecordRepository`
- `OperationIdempotencyService`

新增能力：

- `findExpired(LocalDateTime now, int limit)`：按 `expires_at` 查询过期幂等记录，供后续清理任务使用。
- `OperationIdempotencyService.begin(...)` 运行期重载：支持保存 `instance_id` 和 `task_id`。
- `OperationIdempotencyService.beginOrReplay(...)` 运行期重载：保留原决策语义，支持运行期上下文。

状态语义不变：

- `NEW`：首次插入 `PROCESSING`。
- `REPLAY_SUCCESS`：返回已保存 `result_json`。
- `REPLAY_FAILED`：返回已保存 `error_code`。
- `IN_PROGRESS`：租约未过期。
- `TAKE_OVER`：同请求租约过期后接管。
- `CONFLICT`：同一 `operationId` 对应不同 `actionType` 或 `requestHash`。

### process_active_task / process_instance / process_task_group

实现位置：

- `ActiveTaskRepository.findById`
- `ActiveTaskRepository.findByInstanceId`
- `ProcessInstanceRepository.findById`
- `TaskGroupRepository.findById`

用途：

- `RuntimeStateValidator` 只读取这些表，不写状态。
- 任务动作先按 `taskId` 查活动任务，再用任务上的 `instance_id` 查实例。
- 任务组读取使用当前表字段 `branch_state_json`。

### process_history_task

实现位置：

- `ProcessHistoryTaskRepository`
- `HistoryTaskWriter`
- `ProcessTraceAssembler`
- `DefaultTaskQueryService`

写入规则：

- 审批意见唯一落点是 `process_history_task.comment_text`。
- 流程轨迹主表是 `process_history_task`，没有新增 `process_comment` 或 `process_trace` 表。
- 归档保留 `task_group_id` 和 `branch_key`，支撑后续并行、会签、或签展示。
- 同一 `active_task_id + action_type + operation_id` 重复归档时返回已有历史记录，不重复写入。

查询规则：

- `queryHistoryTasks(instanceId)` 按 `started_at ASC, completed_at ASC, id ASC` 返回完整轨迹。
- `queryComments(instanceId)` 复用历史任务，只返回 `comment_text` 非空白的记录。
- `ProcessCommentDTO.commentId` 使用历史任务 ID。

### process_callback_log

实现位置：

- `ProcessCallbackLogRepository`
- `CallbackOutboxService`
- `WorkflowEventFactory`
- `CallbackLogMapper`
- `DefaultCallbackService`

写入规则：

- `event_id` 是唯一幂等键。
- 推荐并已提供工厂格式：`operationId + ":" + eventType + ":" + sequence`。
- `payload_json` 保存完整 `WorkflowEvent`。
- 重复 `eventId` 且业务字段和载荷一致时跳过，视为幂等。
- 重复 `eventId` 但载荷不同，抛出 `FLOW_CALLBACK_EVENT_CONFLICT`。

投递规则：

- `CallbackOutboxService` 只写 `PENDING`，不调用外部 SPI。
- `DefaultCallbackService.publishCallback(event)` 调用 `WorkflowCallbackHandler`。
- 处理成功后标记 `SUCCESS`。
- 处理失败后标记 `FAILED`，`retry_count + 1`，写入 `last_error`，不向主流程继续抛出。

## 4. B 线接入方式

任务办理类动作建议顺序：

1. B 线生成稳定 `requestHash`，字段覆盖 `taskId/actionType/variables/comment/expectedTaskVersion`。
2. 调用 `OperationIdempotencyService.beginOrReplay(operationId, instanceId, taskId, actionType, operatorId, requestHash, now)`。
3. `NEW` 或 `TAKE_OVER` 才进入业务执行；`REPLAY_SUCCESS/REPLAY_FAILED/IN_PROGRESS/CONFLICT` 按决策返回或抛错。
4. 调用 `RuntimeStateValidator.validateTaskAction(taskId, expectedTaskVersion, actionType, operator)`。
5. B 线执行 `ActiveTaskRepository.complete/cancel/claim/...` CAS 更新。
6. CAS 成功后调用 `HistoryTaskWriter.archiveCompletedTask(...)`。
7. B 线创建下一任务或办结实例。
8. 调用 `CallbackOutboxService.appendPendingBatch(...)` 写回调日志。
9. 调用 `OperationIdempotencyService.markSuccess(operationId, resultJson)` 保存首次返回快照。

关键边界：

- `RuntimeStateValidator` 不能替代 CAS；CAS 返回 0 时不得写历史、回调或下一任务。
- `HistoryTaskWriter` 应在活动任务 CAS 成功后调用。
- `CallbackOutboxService` 应与主业务写入处于同一事务。
- 外部 `WorkflowCallbackHandler` 调用应在主事务提交后执行。

## 5. 稳定错误码

新增运行期错误码集中在 `RuntimeErrorCodes`：

- `FLOW_OPERATOR_REQUIRED`
- `FLOW_INSTANCE_NOT_FOUND`
- `FLOW_INSTANCE_STATUS_INVALID`
- `FLOW_TASK_NOT_FOUND`
- `FLOW_TASK_STATUS_INVALID`
- `FLOW_TASK_CONCURRENT_MODIFIED`
- `FLOW_TASK_GROUP_NOT_FOUND`
- `FLOW_TASK_GROUP_STATUS_INVALID`
- `FLOW_TASK_GROUP_CONCURRENT_MODIFIED`
- `FLOW_CALLBACK_EVENT_CONFLICT`
- `FLOW_HISTORY_ARCHIVE_INVALID`

确定性失败时，外层运行时 Service 可捕获 `RuntimeValidationException#getErrorCode()`，再调用 `OperationIdempotencyService.markFailed(operationId, errorCode)`。
