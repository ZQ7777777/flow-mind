# 实习生 C 技术实现说明

本文件记录 C 线已冻结或待落地的技术契约，避免与实施计划重复。后续 M1～M6 按阶段追加实际实现说明；只有已经通过测试并形成提交的内容，才在“已落地”措辞中登记。

## M0：SPI、Starter 与外围契约

### 位置与边界

- 公共 API 包：`com.flowmind.platform.api`，位于 `platform-core`。
- Starter 包：`com.flowmind.platform.starter`，位于 `platform-starter`。
- 使用 Java 8 JavaBean 和接口：公开无参构造、字段与 getter/setter；不使用 Lombok、`record` 或 Java 9+ API。
- M0 不包含流程状态推进、流程定义 CRUD、Repository 生产实现、SQLite 表结构迁移、HTTP 回调生产投递或业务权限规则。

### SPI 契约

```text
api.spi
├─ ApproverResolver
├─ FileStorageProvider
├─ AttachmentAccessProvider
├─ MessagePublisher
├─ WorkflowCallbackHandler
├─ DelegateProvider
├─ CurrentUserProvider
└─ OrganizationProvider
```

| SPI | 责任 |
|---|---|
| `ApproverResolver` | 根据审批人解析请求返回可办理用户列表，不负责创建任务或推进流程 |
| `FileStorageProvider` | 保存、读取、删除文件内容，平台只保存 `storageKey` 和元数据 |
| `AttachmentAccessProvider` | 判断附件上传、查看、下载、删除权限 |
| `MessagePublisher` | 推送催办、提醒、告警和本地回调通知 |
| `WorkflowCallbackHandler` | 处理工作流事件回调，异常不反向阻断主流程 |
| `DelegateProvider` | 查询指定时间点的委托代办关系 |
| `CurrentUserProvider` | 为 REST 或 Starter 场景提供当前用户上下文 |
| `OrganizationProvider` | 查询部门、用户和角色成员信息，并按 ID 查询用户或部门详情 |

关键规则：

- SPI 入参和返回值只使用公共 `api.dto`、`api.request` 或简单 Java 类型；文件与消息 SPI 不暴露 `persistence.entity`；
- SPI 不依赖 Repository、Controller 或业务系统内部类型；
- 附件授权 SPI 缺失、拒绝或异常时，附件访问默认拒绝；
- 回调处理 SPI 失败时，只更新回调日志和必要告警，不回滚主流程；
- 委托关系由宿主系统维护，平台只消费结果；
- 审批人规则和组织架构数据由宿主系统提供，平台只调用 `ApproverResolver` 和 `OrganizationProvider` 获取解析结果与只读快照；
- 当前 Starter 为文件、消息、回调、委托和当前用户 SPI 提供可关闭的本地 Mock；附件授权始终保留 deny-all 安全后备，宿主提供自定义 `AttachmentAccessProvider` 后自动替换；`ApproverResolver` 与 `OrganizationProvider` 由宿主系统实现。

### Starter Service 契约

```text
api.service
├─ ProcessDefinitionService
├─ ProcessRuntimeService
├─ TaskQueryService
├─ AttachmentService
├─ CallbackService
├─ ProcessMonitorService
└─ AdminProcessService
```

| Service | 契约职责 | 主要归属 |
|---|---|---|
| `ProcessDefinitionService` | 流程定义创建、配置、发布状态、灰度、复制、删除和查询 | A 线 |
| `ProcessRuntimeService` | 流程启动、任务动作、认领、实例终止/删除、变量更新和详情查询 | B 线 |
| `TaskQueryService` | 待办、已办、我发起、活动任务、历史任务、审批意见和已阅记录查询 | C 线 |
| `AttachmentService` | 实例附件、任务附件、附件查询、下载、删除和必填校验 | C 线 |
| `CallbackService` | 回调事件发布和回调日志分页查询 | C 线 |
| `ProcessMonitorService` | 手动催办、超时扫描、提醒查询、告警查询和告警处理 | C 线 |
| `AdminProcessService` | 管理端实例、任务、历史、审计和回调日志查询，以及跳转、强制办结入口 | C 线负责查询；A/B 线负责状态修改 |

Service 实现通用规则：

- Controller 和 Starter 不直接访问 Repository，只调用 Service；
- 查询接口不创建幂等记录；
- 修改接口必须能取得 `operationId`，并写审计或回调所需的可追踪数据；
- Starter 与独立 REST 应用复用同一套 Service Bean；
- 当前 Starter 只装配 `TaskQueryService`、`AttachmentService`、`CallbackService` 和 `ProcessMonitorService` 骨架 Bean，并使用 `@ConditionalOnMissingBean` 支持宿主覆盖；
- `ProcessDefinitionService`、`ProcessRuntimeService` 和 `AdminProcessService` 在 M0 只冻结接口，当前 `PlatformAutoConfiguration` 不提供默认 Bean。

### DTO、Request 与 Entity

当前代码没有独立的 `api.query` 或 `api.result` 包，名称以 `Query`、`Result` 结尾的类型统一保存在 `com.flowmind.platform.api.dto`，它们仍属于 DTO；修改和动作入参保存在 `com.flowmind.platform.api.request`。此外，`persistence.entity` 只保留 4 个附件、文件和消息相关的辅助对象。

#### DTO

| DTO | 说明 |
|---|---|
| `PageResult<T>` | 统一分页返回对象 |
| `AttachmentDTO` | 附件元数据返回对象 |
| `AttachmentDownloadDTO` | 附件下载结果，包含元数据和文件内容 |
| `CallbackLogDTO` | 回调日志查询结果 |
| `ReminderDTO` | 提醒或催办记录 |
| `AlertDTO` | 异常告警记录 |
| `AuditLogDTO` | 审计日志 |
| `ReadRecordDTO` | 已阅记录 |
| `DelegateRelationDTO` | 委托关系快照 |
| `WorkflowEvent` | 回调事件载荷 |
| `TodoTaskQuery` / `CompletedTaskQuery` / `StartedInstanceQuery` | 待办、已办和我发起查询条件 |
| `AttachmentQuery` / `AuditLogQuery` / `CallbackLogQuery` | 附件、审计和回调日志查询条件 |
| `ReadRecordQuery` / `ReminderQuery` / `AlertQuery` | 已阅、提醒和告警查询条件 |
| `AdminInstanceQuery` / `AdminTaskQuery` / `AdminHistoryTaskQuery` | 管理端查询条件 |
| `OperationResult` | 通用操作结果，包含 `operationId` 和 `replayed` |
| `TaskActionResult` | 任务动作结果，包含归档任务、新建任务和 `replayed` |
| `ValidationResult` | 流程定义校验结果 |
| `AttachmentTemplateCheckResult` | 必填附件校验结果 |

DTO 面向调用方表达业务含义，不要求和数据库表完全一致。`Query` 和 `Result` 是用途后缀，不代表独立代码分层。查询条件 DTO 不修改数据、不继承 `OperationRequest`；分页查询条件包含 `pageNo` 和 `pageSize`。DTO 中不得出现入金、报销、请假等具体业务字段。

#### Request

| Request | 说明 |
|---|---|
| `SaveInstanceAttachmentRequest` | 保存实例级附件 |
| `SaveTaskAttachmentRequest` | 保存任务级附件 |
| `DeleteAttachmentRequest` | 删除附件 |
| `DownloadAttachmentRequest` | 下载附件 |
| `CheckAttachmentRequest` | 校验必填附件 |
| `RemindTaskRequest` | 手动催办任务 |
| `TimeoutScanRequest` | 超时扫描 |
| `HandleAlertRequest` | 处理或忽略告警 |
| `AttachmentAccessRequest` | 附件授权判断 |
| `StoreFileRequest` | 文件保存 |

修改类 Request 必须携带 `operationId`。任务级修改类 Request 必须携带 `taskId`、`expectedTaskVersion`、`operatorUserId` 和 `comment`。

#### Entity

| Entity | 说明 |
|---|---|
| `AttachmentUploadItem` | 单个上传附件，包含附件编码、归属范围、文件元数据和二进制内容 |
| `FileContent` | 从文件存储 SPI 读取的文件元数据与二进制内容 |
| `StoredFile` | 文件存储 SPI 返回的存储键和文件元数据 |
| `ProcessMessage` | 消息 SPI 使用的消息类型、标题、正文、接收人和扩展载荷 |

这些 Entity 当前是附件、文件和消息 SPI 使用的辅助 JavaBean，不代表 C 线全部数据库表实体，也不直接作为普通分页查询结果。`AttachmentUploadItem` 和 `FileContent` 可以承载二进制内容，`AttachmentDTO` 只保存可公开的附件元数据。

### 回调事件模型

`WorkflowEvent` 是 C 与 A/B 运行时之间的回调载荷契约。

关键字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `eventId` | `String` | 全局唯一事件 ID |
| `operationId` | `String` | 触发动作的幂等号 |
| `eventType` | `WorkflowEventTypeEnum` | 工作流事件类型 |
| `processCode` | `String` | 流程编码 |
| `instanceId` | `String` | 流程实例 ID |
| `actionType` | `ActionTypeEnum` | 触发事件的动作类型 |
| `operator` | `UserContext` | 操作人快照 |
| `archivedTasks` | `List<HistoryTaskDTO>` | 本次归档或取消的历史任务 |
| `createdTasks` | `List<TaskDTO>` | 本次创建的活动任务 |
| `variables` | `Map<String, Object>` | 事件发生后的流程变量快照 |
| `occurredAt` | `LocalDateTime` | 事件发生时间 |

规则：

- `eventId` 唯一，重复写入视为回调日志幂等；
- 相同 `operationId` 重试不得生成重复事件；
- 回调日志保存完整事件载荷；
- 回调失败不能阻断主事务，只能更新回调状态和告警。

### 幂等与并发验收基线

`process_operation_record` 的目标字段：

| 字段 | 说明 |
|---|---|
| `operationId` | 调用方生成的全局唯一幂等号 |
| `requestHash` | 规范化请求内容哈希 |
| `operationStatus` | `PROCESSING/SUCCESS/FAILED` |
| `resultJson` | 首次成功结果快照 |
| `errorCode` | 失败错误码 |
| `processingExpiresAt` | 处理中租约截止时间 |
| `expiresAt` | 记录保留截止时间 |

验收用例基线：

- 相同 `operationId + requestHash` 成功重试返回首次结果；
- 相同 `operationId` 携带不同请求返回冲突；
- `PROCESSING` 未过期返回处理中；
- `PROCESSING` 租约过期允许同一请求接管；
- 事务回滚时不留下成功状态；
- 并发审批只生成一条历史、一组后续任务和一条回调；
- 并发认领只有一个请求获得任务；
- 并行汇聚最后分支只推进一次；
- 同一实例同一用户重复已阅只保留一条记录；
- 同一任务同一提醒窗口不重复发送提醒。

### Starter 自动装配

`platform-starter` 负责装配，不负责业务实现。

要求：

- `PlatformAutoConfiguration` 装配 core 中的 Service；
- `PlatformProperties` 集中管理开关和 Mock 配置；
- Service 和 SPI 使用 `@ConditionalOnMissingBean`；
- Mock SPI 仅用于本地演示和测试；附件授权的 deny-all 安全后备不属于可关闭的放行 Mock；
- 宿主系统提供生产 SPI Bean 后，对应默认 Mock 或附件授权安全后备不再生效；
- Starter 消费方和独立 REST 应用必须通过同一组核心 Service 测试。

## 已知阶段边界

- C 的查询层可以读取 A/B 写入的数据，但不能绕过运行时状态机修改流程状态。
- C 的附件能力只保存元数据和调用文件 SPI，不把文件二进制写入普通查询 DTO。
- C 的回调能力治理投递状态，不替代 B/A 的主事务。
- C 的 Mock 只服务测试，不提供生产级权限、文件、消息、委托或回调实现。
- M0 的测试夹具只证明契约和验收结构，不代表完整业务流程已经闭环。
