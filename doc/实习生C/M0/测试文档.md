## C0.3 DTO、Request 与 Entity 契约测试

### 测试目标

- 公共对象只使用 `api.dto` 和 `api.request` 两个 API 包，不存在独立的 `api.query`、`api.result` 包。
- 名称以 `Query`、`Result` 结尾的类型位于 `api.dto`。
- `persistence.entity` 只保留附件上传、文件存储和消息所需的 4 个辅助对象。
- 修改请求携带 `operationId`。
- 任务级请求携带 `taskId`、`expectedTaskVersion`、`operatorUserId` 和 `comment`。
- DTO 包中的运行时动作结果能表达归档任务、新建任务和幂等重放。
- 附件上传对象能承载二进制内容。

### 覆盖文件

| 测试类 | 覆盖点 |
| --- | --- |
| 代码目录核对 | `api.dto`、`api.request` 和 4 个辅助 Entity 的实际结构 |
| `OperationRequestContractTest` | `OperationRequest` 和 `TaskOperationRequest` JavaBean 契约 |
| `RuntimeRequestContractTest` | 运行时与 C 线修改请求字段、任务版本、附件上传内容 |
| `RuntimeResultContractTest` | DTO 包内的 `TaskActionResult`、`OperationResult`、运行时 DTO 以及 `AttachmentUploadItem` 可表达性 |

### 验证结果

| 检查项 | 结果 |
| --- | --- |
| `Query`、`Result` 命名类统一位于 `api.dto` | 通过 |
| 不存在独立 `api.query`、`api.result` 包 | 通过 |
| `AttachmentUploadItem`、`FileContent`、`StoredFile`、`ProcessMessage` 为当前 4 个辅助 Entity | 通过 |
| `operationId` 字段可读写 | 通过 |
| 任务级请求继承 `TaskOperationRequest` | 通过 |
| `expectedTaskVersion` 字段可读写 | 通过 |
| 修改请求夹具唯一覆盖 | 通过 |
| 附件二进制内容可读写 | 通过 |
| `TaskActionResult.archivedTasks/createdTasks/replayed` 可表达 | 通过 |

### 执行命令

```powershell
mvn -q -pl platform/platform-core -am test
```

## C0.5 幂等与并发验收基线测试

### 测试目标

- 建立后续 A/B 可复用的幂等和并发断言结构。
- 不实现生产流程引擎，只用内存假实现证明验收语义。

### 覆盖文件

| 测试类 | 覆盖点 |
| --- | --- |
| `OperationRecordContractTest` | `OperationRecordDTO` 字段和 JavaBean 契约 |
| `IdempotencyAcceptanceBaselineTest` | 幂等重放、冲突、处理中租约、租约接管、失败结果、回滚、并发副作用唯一 |

### 验证结果

| 检查项 | 结果 |
| --- | --- |
| 相同 `operationId + requestHash` 成功重放 | 通过 |
| 相同 `operationId` 不同 `requestHash` 冲突 | 通过 |
| `PROCESSING` 未过期返回处理中 | 通过 |
| `PROCESSING` 租约过期可接管 | 通过 |
| `FAILED` 返回已记录错误码 | 通过 |
| 事务回滚不留下 `SUCCESS` | 通过 |
| 并发任务动作只产生一次历史、下一任务和回调 | 通过 |

### 执行命令

```powershell

```
