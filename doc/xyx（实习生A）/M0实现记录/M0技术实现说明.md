# 实习生 A 技术实现说明

本文件记录已落地的技术契约，避免与完整设计文档和实施计划重复。后续阶段按实际交付追加实现说明。

## M0：数据模型与流程定义 DTO

### 位置与边界

- 数据库脚本：`platform/platform-core/src/main/resources/schema/sqlite/001_init_flow_platform.sql`。
- DTO 代码包：`com.flowmind.platform.api.dto`，位于 `platform-core`。
- 工程基线为 Java 8；流程定义 DTO 使用 Lombok `@Data` 生成访问方法，并实现 `Serializable`。
- M0 负责冻结 SQLite 数据结构和流程定义返回契约，不包含 Repository、流程定义服务、运行时流转、Starter 自动装配或数据库迁移框架。

### SQLite 初始化模型

初始化脚本使用 `CREATE TABLE/INDEX IF NOT EXISTS`，一次创建 17 张业务表，并通过外键、唯一约束、`CHECK` 约束和索引固化 M0 数据契约。

```text
流程定义期
├─ process_definition
├─ process_node
├─ process_edge
├─ process_form_field
├─ process_attachment_template
└─ process_definition_attachment_config

流程运行期
├─ process_instance
├─ process_task_group
├─ process_active_task
├─ process_history_task
├─ process_read_record
├─ process_attachment
├─ process_audit_log
├─ process_callback_log
├─ process_reminder_record
├─ process_alert_record
└─ process_operation_record
```

### 数据库关键约束

| 范围 | 已落地约束 |
| --- | --- |
| 流程定义 | `process_code + version` 唯一；同一流程编码只允许一个全量激活版本；灰度开启时必须提供灰度规则 |
| 节点与连线 | 节点编码、连线编码在定义内唯一；节点类型受枚举检查约束；同一来源节点最多一条默认出线 |
| 表单与附件配置 | 表单字段编码在定义内唯一；附件模板按编码和版本唯一；必填附件的最小数量不得为 0 |
| 任务并发 | `process_active_task`、`process_task_group` 均包含非负 `lock_version`，默认值为 `0` |
| 历史与幂等 | 历史任务按活动任务、动作和操作号去重；`process_operation_record.operation_id` 全局唯一 |
| 状态数据 | 定义、实例、任务、任务组、回调、催办、告警和操作记录等状态字段均通过 `CHECK` 限定取值 |
| 关联关系 | 定义期子表和主要运行期表建立外键；审计、告警等保留型记录按业务语义使用 `SET NULL` 或逻辑关联 |

脚本还为定义查询、待办查询、实例查询、历史任务、附件、审计、回调、催办、告警和幂等记录建立索引，支持后续服务层按主要访问路径查询。

### 流程定义 DTO 结构

```text
ProcessDefinitionDTO
└─ ProcessDefinitionDetailDTO
   ├─ List<ProcessNodeDTO> nodes
   ├─ List<ProcessEdgeDTO> edges
   ├─ List<ProcessFormFieldDTO> formFields
   └─ List<ProcessAttachmentTemplateDTO> attachmentTemplates
```

- `ProcessDefinitionDTO`：承载定义 ID、流程编码和名称、系统编码、版本、定义/激活/灰度状态、灰度规则及创建更新信息。
- `ProcessDefinitionDetailDTO`：继承概要 DTO，聚合节点、连线、表单字段和附件模板配置；四个集合在对象创建时独立初始化为空列表。
- `ProcessNodeDTO`：表达节点类型、配对网关、审批人规则、多人审批模式、监听/超时/催办配置、画布坐标和排序。
- `ProcessEdgeDTO`：表达来源节点、目标节点、条件表达式、默认出线标识和排序。
- `ProcessFormFieldDTO`：表达字段数据类型、控件类型、必填标识、校验规则、默认值和展示顺序。
- `ProcessAttachmentTemplateDTO`：合并全局附件模板版本与流程定义附件配置，表达配置组、生效状态、扩展名、大小限制、数量限制和适用节点。

### DTO 与数据库映射边界

- DTO 面向 API 返回，不直接作为 SQLite 持久化实体；JSON 配置在 DTO 中以 `String` 表达，列表型展示字段使用 `List<String>`。
- 数据库中的状态字段当前在 DTO 中使用 `String`，用于承载 M0 已冻结状态值；DTO 本身不执行状态转换或合法性校验。
- `ProcessAttachmentTemplateDTO` 是组合返回对象，对应附件模板与定义附件配置两类数据，不等同于单张表记录。
- 时间字段使用 `LocalDateTime`，版本和排序使用 `Integer`，文件大小使用 `Long`，布尔语义使用 `Boolean`。

### 契约测试

- `FlowPlatformSchemaTest` 在 SQLite 内存数据库中执行完整初始化脚本，验证脚本可执行，以及流程版本唯一、灰度规则、节点编码/类型和必填附件数量等约束能够生效。
- `ProcessDefinitionDtoContractTest` 验证详情 DTO 的四个集合非空、初始为空且实例间相互独立，并验证定义信息与节点、连线、表单、附件配置可以完整组装。
- 验证命令：`mvn -q -pl platform/platform-core -am test`。

### 已知阶段边界

- M0 的数据库测试验证结构和代表性约束，不代替后续 Repository 集成测试、事务测试、并发测试或完整迁移回滚测试。
- DTO 契约只证明定义数据可表达，不包含请求参数校验、JSON 序列化定制、枚举转换、数据库映射或业务服务逻辑。
- 数据库文件创建、连接配置、Schema 自动初始化和环境升级策略留待后续 Starter 与持久化阶段实现。
