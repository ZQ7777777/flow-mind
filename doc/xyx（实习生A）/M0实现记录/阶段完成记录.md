### A0.0 说明

- M0 的唯一目标是冻结后续 M1-M6 依赖的数据模型、状态模型和并发契约，不实现流程定义 CRUD、运行时推进或外部 SPI。
- A 线对 B 线输出 `lock_version`、`TaskDTO.taskVersion` 映射、状态边界和并发错误码语义；对 C 线输出 `operation_id`、`event_id`、操作记录和事务不变量。
- 现有完成记录无法补充真实提交号，因为当前环境中 `git` 命令不可用；后续可在具备 Git 环境时回填。

### A0.1 说明

- SQLite 脚本一次创建定义期 6 张表和运行期 11 张表，并使用 `CREATE TABLE/INDEX IF NOT EXISTS` 支持重复初始化。
- 关键冻结点包括 `process_code + version`、定义内节点/连线/字段编码唯一、附件模板版本唯一、历史任务幂等唯一、操作号唯一和回调事件号唯一。
- `process_active_task` 与 `process_task_group` 均已包含非负 `lock_version`，为 B 线运行时请求的 `expectedTaskVersion` 提供持久化基础。

### A0.2 说明

- 实体统一放在 `platform-core`，只作为持久化对象；DTO 仍面向 API 返回，不直接复用为数据库实体。
- `ProcessActiveTaskEntity.lockVersion` 对应查询侧任务版本；`ProcessTaskGroupEntity.branchStateJson` 承载并行分支状态。
- M0 未引入正式 Java enum，状态字段仍以冻结字符串值表达。

### A0.3 说明

- 活动任务更新统一匹配 `id + 允许状态 + lock_version`，成功后版本加一，返回受影响行数。
- 任务组更新统一匹配 `group_status=ACTIVE + lock_version`；会签计数不能超过 `total_count`，并行分支只有处于 `RUNNING` 时才能到达。
- Repository 不做完整审批推进、历史归档、回调发送或重试编排；这些留给后续运行时服务。

### A0.4 说明

- 状态校验器只表达冻结规则，不触发发布、激活、流转或数据库写入。
- 模型校验器以 `ProcessDefinitionDetailDTO` 为输入，覆盖最小发布前结构规则：开始/结束节点、节点连线引用、审批人规则、条件网关默认线、并行网关配对和可达性。
- 校验失败统一使用 `FrozenValidationException` 与 `FrozenValidationErrorCodes`，避免被包装成无语义的通用异常。
