# 实习生 A 技术实现说明

本文件记录已落地的技术契约，避免与完整设计文档和实施计划重复。后续 M1-M6 按阶段追加实际实现说明。

## M0：数据模型、状态与乐观锁契约

### 位置与边界

- 数据库脚本：`platform/platform-core/src/main/resources/schema/sqlite/001_init_flow_platform.sql`。
- 持久化实体包：`com.flowmind.platform.persistence.entity`，位于 `platform-core`。
- Repository 包：`com.flowmind.platform.persistence.repository`，基于 Spring JDBC `JdbcTemplate`。
- 状态与模型校验包：`com.flowmind.platform.core.validation`。
- 工程基线为 Java 8、Spring Boot 2.7.18、Spring JDBC、SQLite；实体使用 Lombok `@Data`，不承载业务逻辑。
- M0 冻结数据结构、状态取值、模型校验规则和乐观锁条件更新原语，不包含流程定义 CRUD、发布激活服务、运行时流转引擎、附件文件存储、外部 SPI、Starter 自动装配或 REST Controller。

### SQLite 初始化模型

初始化脚本使用 `CREATE TABLE/INDEX IF NOT EXISTS`，并启用 `PRAGMA foreign_keys = ON`。脚本一次创建 17 张业务表。

```text
流程定义期
├─ process_definition
├─ process_node
├─ process_edge
├─ process_form_field
├─ process_attachment_template
└─ process_definition_attachment_config

流程运行期
├─ process_instance
├─ process_task_group
├─ process_active_task
├─ process_history_task
├─ process_read_record
├─ process_attachment
├─ process_audit_log
├─ process_callback_log
├─ process_reminder_record
├─ process_alert_record
└─ process_operation_record
```

### 数据库关键约束

| 范围 | 已冻结约束 |
| --- | --- |
| 流程定义 | `process_code + version` 唯一；同一流程编码只允许一个全量激活版本；灰度开启时必须提供 `gray_rule_config` |
| 节点与连线 | 定义内节点编码、连线编码唯一；节点类型限定为开始、用户任务、条件网关、并行分支、并行汇聚和结束；同一来源节点最多一条默认出线 |
| 表单与附件 | 定义内字段编码唯一；附件模板按 `attachment_code + template_version` 唯一；必填附件 `min_count >= 1` |
| 任务并发 | `process_active_task` 和 `process_task_group` 均包含 `lock_version INTEGER NOT NULL DEFAULT 0 CHECK(lock_version >= 0)` |
| 任务组 | `total_count`、`completed_count` 非负；任务组状态限定为 `ACTIVE/COMPLETED/CANCELED`；分支状态保存在 `branch_state_json` |
| 历史与幂等 | 历史任务按 `active_task_id + action_type + operation_id` 去重；`process_operation_record.operation_id` 全局唯一 |
| 回调 | `process_callback_log.event_id` 唯一，按操作号和事件语义生成稳定事件标识 |
| 保留型记录 | 审计、告警等表按业务语义使用 `SET NULL` 或逻辑关联，避免删除实例后破坏幂等与排障记录 |

脚本同时为定义查询、待办查询、实例查询、历史、附件、审计、回调、催办、告警和操作记录建立索引。

### 持久化实体

- 17 张表均有对应实体，统一放在 `com.flowmind.platform.persistence.entity`。
- 实体字段使用 camelCase，对应 SQLite 下划线列名；JSON 配置字段使用 `String`，时间字段使用 `LocalDateTime`。
- ID、状态、编码、操作号等字段使用 `String`；版本、计数、排序和大小字段按语义使用 `Integer`、`Long`。
- 实体只作为持久化数据承载对象，不实现状态迁移、并发判断、SQL 操作或 DTO 复用逻辑。
- `ProcessActiveTaskEntity.lockVersion` 是查询侧 `TaskDTO.taskVersion` 的持久化来源。
- `ProcessTaskGroupEntity.branchStateJson` 使用出线 `edge_code` 作为分支键，值为 `RUNNING/ARRIVED/CANCELED`。

### 状态与枚举取值

| 模型 | 冻结取值 |
| --- | --- |
| 节点类型 | `START`、`USER_TASK`、`EXCLUSIVE_GATEWAY`、`PARALLEL_SPLIT_GATEWAY`、`PARALLEL_JOIN_GATEWAY`、`END` |
| 定义状态 | `DRAFT`、`PUBLISHED`、`ARCHIVED` |
| 激活状态 | `INACTIVE`、`ACTIVE` |
| 灰度状态 | `OFF`、`ON` |
| 实例状态 | `NOT_STARTED`、`RUNNING`、`COMPLETED`、`ARCHIVED`、`TERMINATED` |
| 活动任务状态 | `ACTIVE`、`CLAIMED`、`COMPLETED`、`CANCELED` |
| 任务组类型 | `OR_SIGN`、`COUNTERSIGN`、`PARALLEL_GATEWAY` |
| 任务组状态 | `ACTIVE`、`COMPLETED`、`CANCELED` |
| 分支状态 | `RUNNING`、`ARRIVED`、`CANCELED` |
| 操作状态 | `PROCESSING`、`SUCCESS`、`FAILED` |
| 回调状态 | `PENDING`、`SUCCESS`、`FAILED` |
| 催办状态 | `PENDING`、`SENT`、`FAILED` |
| 告警状态 | `OPEN`、`HANDLED`、`IGNORED` |

状态字段当前以 `String` 形式落入 DDL、实体和校验器；M0 不引入正式 Java enum 类型。

### 乐观锁 Repository

`ActiveTaskRepository` 提供活动任务原子条件更新原语：

- `complete(id, expectedLockVersion)`：将 `ACTIVE/CLAIMED` 任务标记为 `COMPLETED`。
- `cancel(id, expectedLockVersion)`：将 `ACTIVE/CLAIMED` 任务标记为 `CANCELED`。
- `claim(id, expectedLockVersion, assigneeUserId, assigneeUserName)`：仅允许 `ACTIVE -> CLAIMED`。
- `unclaim(id, expectedLockVersion)`：仅允许 `CLAIMED -> ACTIVE`，并清空办理人。
- `transfer(id, expectedLockVersion, assigneeUserId, assigneeUserName)`：仅允许在 `ACTIVE/CLAIMED` 状态下变更办理人。

所有活动任务更新都匹配 `id + 允许的当前状态 + lock_version`，成功后 `lock_version + 1`，返回受影响行数。返回 `0` 表示任务不存在、状态不允许或版本过期，由上层映射为 `FLOW_TASK_CONCURRENT_MODIFIED`。

`TaskGroupRepository` 提供任务组条件更新原语：

- `incrementCompletedCount(id, expectedLockVersion)`：会签计数原子增加，达到 `total_count` 时同时完成任务组。
- `markBranchArrived(id, branchKey, expectedLockVersion)`：仅当 JSON 中对应分支仍为 `RUNNING` 时标记 `ARRIVED` 并增加计数。
- `complete(id, expectedLockVersion)` 与 `cancel(id, expectedLockVersion)`：仅允许 `ACTIVE` 任务组进入终态。
- `findBranchStateJson(id)`：读取分支状态快照，供有限重试或上层判断使用。

任务组冲突在 Repository 层不自动重试；调用方有限重试耗尽后映射为 `FLOW_TASK_GROUP_CONCURRENT_MODIFIED`。

### 状态与模型校验器

```text
DefinitionStatusValidator
├─ 校验 DRAFT/PUBLISHED/ARCHIVED 与 INACTIVE/ACTIVE、OFF/ON 的冻结组合
└─ 灰度 ON 必须携带 grayRuleConfig

ProcessInstanceStatusValidator
└─ NOT_STARTED -> RUNNING -> COMPLETED/TERMINATED -> ARCHIVED

ActiveTaskStatusValidator
└─ ACTIVE <-> CLAIMED；ACTIVE/CLAIMED -> COMPLETED/CANCELED

TaskGroupStatusValidator
├─ ACTIVE -> COMPLETED/CANCELED
├─ 校验 completed_count 与 total_count
└─ 校验并行分支到达前 group_status、计数上限和 branch_key 状态

OperationRecordStatusValidator
└─ PROCESSING -> SUCCESS/FAILED

DefinitionModelValidator
├─ 有且仅有一个开始节点，至少一个结束节点
├─ 节点和连线引用合法且编码不重复
├─ 用户任务必须有审批人规则
├─ 条件网关最多一条默认出线
├─ 并行分支和汇聚网关必须正确配对
└─ 节点必须从开始可达，并能到达结束节点
```

校验失败统一使用 `FrozenValidationException` 和 `FrozenValidationErrorCodes`，不以通用运行时异常表达冻结规则失败。

### DTO 与模型校验输入

- 流程定义返回 DTO 位于 `com.flowmind.platform.api.dto`。
- `ProcessDefinitionDetailDTO` 继承定义概要 DTO，并聚合 `nodes`、`edges`、`formFields`、`attachmentTemplates` 四组明细。
- `DefinitionModelValidator` 以 `ProcessDefinitionDetailDTO` 为输入，校验节点、连线、审批人规则和网关配对等 M0 最小发布前结构规则。
- DTO 面向 API 可表达性，不直接作为数据库实体；附件模板 DTO 是模板与定义附件配置的组合返回对象。

### 契约测试

- `FlowPlatformSchemaTest` 使用 SQLite 内存库执行完整初始化脚本，验证脚本可执行，以及流程版本唯一、灰度规则、节点编码/类型和必填附件数量等代表性约束生效。
- `TaskRepositoryIntegrationTest` 覆盖活动任务同版本只能完成一次、非法状态和过期版本返回 `0`、任务组计数不超界、同一并行分支不重复到达、冲突错误码稳定。
- `FrozenStatusValidatorTest` 覆盖定义状态组合、实例状态迁移、任务状态迁移、任务组状态/计数/分支到达和操作记录状态迁移。
- `DefinitionModelValidatorTest` 覆盖有效模型、重复或缺失开始/结束节点、非法连线引用、用户任务无审批人、条件网关默认线、并行网关配对和孤立节点。
- `ProcessDefinitionDtoContractTest` 验证流程定义 DTO 明细集合默认初始化、实例间隔离和定义模型可完整组装。
- 验证命令：`mvn -q -pl platform/platform-core -am test`。

### 与 B、C 线的冻结接口

- 向 B 线提供 `lock_version`、`TaskDTO.taskVersion` 映射来源、活动任务条件更新规则、任务组并发错误码和状态边界。
- 向 C 线提供 `operation_id` 关联字段、`event_id` 唯一规则、操作记录幂等字段、事务内一致性和并发验收不变量。
- 所有状态修改请求必须携带 `operationId`；任务级修改必须同时携带 `expectedTaskVersion`。
- 操作记录的 `instance_id/task_id` 保持逻辑关联，避免实例或任务删除后破坏幂等重试和审计追踪。

### 已知阶段边界

- M0 的 Repository 只提供持久化原语，不实现完整审批推进、历史归档、后续任务创建、回调发送或重试编排。
- 数据库约束和校验器只表达冻结规则，不替代服务层权限校验、请求非空校验、JSON 结构校验或完整发布流程。
- SQLite 脚本是当前工程基线；Oracle、国产数据库适配和迁移框架留待后续阶段。
- 乐观锁失败、幂等冲突、任务组有限重试和事务回滚的完整业务处理留待运行时服务阶段实现。
