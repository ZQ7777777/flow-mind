## 1. 收口结论

实习生A 的 M1 核心开发范围已经形成可验收实现：流程定义可以创建、查询、分页检索、保存完整流程图、复制为下一草稿版本，并可按定义级策略删除。节点、连线、表单字段和定义附件配置绑定在同一服务事务中保存、复制或删除。

定义变更后的缓存处理已经收敛到现有 `ProcessDefinitionCache`：保存图、复制定义和删除定义提交后调用 `invalidate(definitionId)` 精确失效定义级缓存。旧图缓存失效 SPI 已删除，不再作为 A/B 协作契约。

本阶段没有重复实现 B 线的发布前校验、运行时流程图解析和运行时定义加载策略，也没有替代 C 线实现附件模板主数据、文件存储和附件运行时管理。A 线只在定义维度保存 `formFields` 与 `attachmentConfigs` 的绑定数据，以保证完整定义快照可被后续 B/C 联调用例读取。

## 4. 当前可验收能力

- 同一 `processCode` 创建定义时版本号递增，新定义固定为 `DRAFT + INACTIVE + OFF`。
- 创建、保存图、复制、删除均接入定义动作命名空间的 `operationId` 幂等记录。
- 同号同请求成功重放返回首次结果，同号不同请求返回幂等冲突。
- 保存入金申请 5 节点 4 连线后，详情查询可按稳定顺序返回节点、连线和定义期扩展绑定。
- 节点编码重复、连线编码重复、连线引用不存在节点、非可编辑定义保存图均会失败。
- 保存图过程中节点、连线、表单字段或附件配置任一环节失败时，事务整体回滚。
- 复制定义会生成下一草稿版本，重建数据库主键，保留业务编码和配置内容。
- 删除定义会清理定义期扩展、运行期子表、实例、连线、节点和定义主表，保留审计、回调和幂等记录。
- 保存、复制、删除在事务提交后通过 `ProcessDefinitionCache.invalidate(definitionId)` 失效缓存；事务回滚和幂等成功重放不重复触发。
- Starter 在存在 `JdbcTemplate` 时可自动装配定义管理相关 Repository、幂等组件、缓存组件和 `ProcessDefinitionService`。

## 7. 风险与后续建议

- 当前定义没有 `lock_version`，并发整图编辑仍可能以后提交覆盖先提交；如前端需要多人协作编辑，应在后续阶段引入定义级乐观锁。
- `ProcessDefinitionCache` 当前是单 JVM 内存缓存；如平台部署为多实例，需要后续补充跨实例缓存失效机制。
- 发布和运行期校验仍需 B 线接入最新 `getDefinition` 快照后完成联调确认。
- 附件模板和文件规则仍需 C 线在真实数据落地后补充联调用例。
