# 实习生A：M1 技术实现说明

阶段：M1 流程定义管理  
负责人：实习生A（徐雨新）  
更新日期：2026-07-21  
技术基线：Java 8、Spring Boot 2.7.18、Spring JDBC、SQLite

## 1. 实现边界

M1 的 A 线实现聚焦流程定义编辑态能力：定义创建、详情查询、分页检索、整图保存、定义复制、定义级删除、版本分配、定义期表单字段绑定、定义期附件配置绑定，以及写操作幂等。

A 线 M1 不承载以下内容：

- 发布、激活、停用、归档、灰度发布等完整状态治理；
- B 线的发布前校验、运行时流程图解析和运行时定义加载逻辑；
- C 线的附件模板主数据、文件存储和附件运行时管理；
- 运行时实例启动、审批流转、任务归档和回调投递。

`validateForPublish`、`publish`、`activate`、`deactivate`、`archive`、`enableGray`、`disableGray` 在当前实现中仍为接口占位，默认抛出 `UnsupportedOperationException`。

## 2. 当前代码结构

M1 相关代码集中在 `platform-core`：

```text
platform/platform-core/src/main/java/com/flowmind/platform
├── api
│   ├── dto                         # 定义、节点、连线、表单、附件配置 DTO
│   ├── request                     # 创建、保存图、复制、删除等请求
│   ├── enums                       # 定义状态、动作类型、节点类型等枚举
│   └── service/ProcessDefinitionService.java
├── core
│   ├── definition                  # 定义服务、映射、草稿工厂、幂等、缓存
│   └── validation                  # 请求校验、模型校验、状态校验
└── persistence
    ├── entity                      # SQLite 表实体
    └── repository                  # Spring JDBC Repository
```

`platform-starter` 只负责自动配置，不重复实现定义管理业务逻辑。存在 `JdbcTemplate` 时，自动装配 Repository、`OperationIdempotencyService`、`ProcessDefinitionCache` 和 `ProcessDefinitionService`。

## 3. 核心服务实现

默认实现为 `DefaultProcessDefinitionService`。

| 方法 | M1 行为 |
| --- | --- |
| `createDefinition` | 校验创建请求，按 `processCode` 分配下一版本，插入 `DRAFT + INACTIVE + OFF` 定义，并记录幂等成功结果。 |
| `saveGraph` | 校验定义可编辑，归一化节点、连线、表单字段和附件配置，执行图结构校验，在一个事务内全量替换定义图和扩展绑定。 |
| `copyDefinition` | 读取源定义完整快照，创建同一 `processCode` 下的下一草稿版本，复制节点、连线、表单字段和附件配置，并重建数据库主键。 |
| `deleteDefinition` | 禁止删除激活定义，按依赖顺序清理定义期和运行期子表，保留审计、回调和幂等记录。 |
| `getDefinition` | 返回定义基础信息、节点、连线、表单字段和附件配置绑定。 |
| `searchDefinitions` | 使用公共分页查询对象检索定义列表，并统一分页默认值和上限。 |
| `listNodes` | 返回指定定义下按仓储规则排序后的节点列表。 |

## 4. 整图保存与模型校验

`saveGraph` 采用完整请求替换当前草稿图，主要处理顺序如下：

1. 校验 `definitionId`、`operationId`、`operatorUserId`、节点列表和连线列表。
2. 读取定义并校验必须处于 `DRAFT + INACTIVE + OFF`。
3. 使用 `DefinitionGraphDraftFactory` 归一化节点、连线、表单字段和附件配置，包括补齐定义 ID、主键、默认排序和默认值。
4. 基于归一化后的内容计算幂等摘要，调用 `OperationIdempotencyService.beginOrReplay`。
5. 使用 `DefinitionModelValidator.validateSaveGraphStructure` 校验保存图结构。
6. 在事务内先删旧连线、旧节点，再插入新节点、新连线。
7. 同事务替换 `process_form_field` 和 `process_definition_attachment_config`。
8. 更新定义 `updated_by`、`updated_at`，写入幂等成功结果。
9. 事务提交后失效当前定义的图缓存。

`DefinitionModelValidator` 当前覆盖的关键规则包括：节点和连线编码非空且不重复、节点类型合法、连线引用存在、必须有且仅有一个开始节点、至少一个结束节点、开始/用户任务出边约束、用户任务审批人规则、网关审批和多实例禁用、排他网关条件与默认分支、并行网关配对与分支路径、循环检测、开始和结束可达性，以及表单字段和附件配置的基础合法性。

## 5. 复制与版本分配

复制定义以源定义的 `processCode` 为版本组，不把请求中的编码作为 M1 改编码入口。新定义固定为草稿态：

- `definitionStatus = DRAFT`
- `activationStatus = INACTIVE`
- `grayStatus = OFF`

实现会查询当前 `processCode` 最大版本并插入 `version + 1`。数据库唯一约束 `process_code + version` 作为并发兜底；发生版本冲突时，`copyDefinition` 会在有限次数内重新读取最大版本并重试。

复制节点、连线、表单字段和附件配置时会重建数据库主键，同时保留节点编码、连线编码、字段编码、附件配置业务编码和配置内容。

## 6. 定义级删除策略

`deleteDefinition` 删除单个定义版本，不按 `processCode` 批量删除其他版本。删除前要求目标定义存在，并且 `activation_status != ACTIVE`。

事务内删除顺序为：

1. `process_form_field`
2. `process_definition_attachment_config`
3. `process_attachment`
4. `process_read_record`
5. `process_history_task`
6. `process_active_task`
7. `process_task_group`
8. `process_reminder_record`
9. `process_alert_record`
10. `process_instance`
11. `process_edge`
12. `process_node`
13. `process_definition`

`process_audit_log` 和 `process_callback_log` 按 DDL 语义保留，`process_operation_record` 按幂等保留期保留。删除成功后的相同请求重放返回首次删除结果，不再次删除，也不重复触发缓存失效。

## 7. 缓存失效

当前代码已经删除旧图缓存失效 SPI。定义图变更后，`DefaultProcessDefinitionService` 直接依赖 `ProcessDefinitionCache` 的现有方法：

```java
processDefinitionCache.invalidate(definitionId);
```

失效动作由 `registerGraphCacheInvalidation(definitionId)` 注册到事务提交后执行；若当前没有事务同步上下文，则立即执行失效。这样避免事务回滚时提前清理缓存，也避免成功幂等重放重复清理缓存。

`ProcessDefinitionCache` 当前为内存组件，只缓存 `PUBLISHED + ACTIVE` 的定义快照，并通过 generation token 避免失效后旧加载结果回写。

## 8. 幂等实现

定义管理写操作统一使用 `process_operation_record`，动作类型来自 `DefinitionActionTypeEnum`：

- `CREATE`
- `SAVE_GRAPH`
- `COPY`
- `DELETE`

`OperationIdempotencyService.beginOrReplay` 返回以下决策：

| 决策 | 含义 |
| --- | --- |
| `NEW` | 首次请求，已创建 `PROCESSING` 记录。 |
| `REPLAY_SUCCESS` | 同号同请求已成功，直接返回首次结果。 |
| `REPLAY_FAILED` | 同号同请求已确定失败，返回首次错误码语义。 |
| `IN_PROGRESS` | 同号同请求仍在处理租约内。 |
| `TAKE_OVER` | 原处理租约过期，当前请求可接管。 |
| `CONFLICT` | 同一 `operationId` 对应不同动作或请求摘要。 |

成功结果写入 `SUCCESS + result_json`。确定性校验失败会写入稳定错误码，便于调用方重试时获得一致语义。

## 9. 错误码

M1 定义管理错误码集中在 `DefinitionErrorCodes`，核心错误码包括：

| 错误码 | 场景 |
| --- | --- |
| `FLOW_DEFINITION_NOT_FOUND` | 定义不存在。 |
| `FLOW_DEFINITION_INVALID` | 请求字段或图结构非法。 |
| `FLOW_NODE_NOT_FOUND` | 连线引用不存在的节点。 |
| `FLOW_OPERATION_ID_REQUIRED` | 缺少幂等操作号。 |
| `FLOW_OPERATION_ID_CONFLICT` | 同号不同动作或不同请求。 |
| `FLOW_OPERATION_IN_PROGRESS` | 相同请求仍在处理租约内。 |
| `FLOW_DEFINITION_NOT_EDITABLE` | 当前定义不可编辑或不可删除。 |
| `FLOW_DEFINITION_VERSION_CONFLICT` | 版本分配冲突。 |
| `FLOW_DEFINITION_CONCURRENT_MODIFIED` | 定义被其他请求并发修改。 |
| `FLOW_DEFINITION_IN_USE` | 定义已被运行数据使用。 |
| `FLOW_NODE_CODE_DUPLICATED` | 节点编码重复。 |
| `FLOW_EDGE_CODE_DUPLICATED` | 连线编码重复。 |

## 10. B/C 协作点

提供给 B 线的协作点：

- `getDefinition` 返回完整定义快照；
- `listNodes` 返回稳定排序节点；
- 保存图、复制定义、删除定义提交后，通过 `ProcessDefinitionCache.invalidate(definitionId)` 精确失效定义级缓存；
- A 线不实现 B 线的发布校验、运行图解析和运行时加载策略。

提供给 C 线的协作点：

- `SaveProcessGraphRequest.formFields` 按定义维度保存到 `process_form_field`；
- `SaveProcessGraphRequest.attachmentConfigs` 按定义维度保存到 `process_definition_attachment_config`；
- 复制定义时同步复制上述绑定；
- 删除定义时同步清理上述绑定；
- A 线不维护附件模板主数据，不保存文件内容，也不实现附件运行时校验。

## 11. 测试覆盖

当前 M1 阶段保留的核心单元测试聚焦 3 个必须点：

- `DefaultProcessDefinitionServiceTest`：覆盖创建、整图保存、复制、删除、幂等重放和缓存失效。
- `DefinitionRequestValidatorTest`：覆盖请求参数、分页参数和基础校验错误。
- `OperationIdempotencyServiceTest`：覆盖成功重放、失败重放、冲突、处理中和租约接管。

仓库中原有的 `ProcessDefinitionCacheTest` 继续覆盖缓存组件自身行为。此前临时新增的低价值小单元测试已经不作为 M1 必须测试保留范围。

默认冻结验证命令：

```powershell
mvn -q test
```

执行目录为 `platform`。

## 12. 已知边界

- 当前没有引入定义级 `lock_version`；并发整图保存仍以后提交覆盖为主，后续如需要强并发编辑应正式引入乐观锁。
- 发布、激活、停用、归档、灰度接口仍是后续阶段或 B 线协作范围。
- 附件模板名称、模板版本、文件类型和大小限制等主数据不由 A 线 M1 填充。
- A/B/C 联合验收需要在 B/C M1 真实实现合入后另行记录。
