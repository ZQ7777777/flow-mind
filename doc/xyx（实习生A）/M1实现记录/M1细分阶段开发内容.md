## M1 边界调整

M1 的目标是基于当前已合入的公共 API 契约，实现流程定义核心结构的可创建、可查询、可编辑、可复制和可删除能力，为 B 线发布校验/运行缓存和 C 线表单/附件配置提供稳定数据入口。

A 线 M1 主责：

- 实现 `process_definition`、`process_node`、`process_edge` 的 Repository、RowMapper 和集成测试；
- 实现 `ProcessDefinitionService` 中与定义草稿管理直接相关的方法：
  - `createDefinition`；
  - `saveGraph`；
  - `copyDefinition`；
  - `deleteDefinition`；
  - `getDefinition`；
  - `searchDefinitions`；
  - `listNodes`；
- 复用现有 DTO、request、enum、service 接口，不另起一套契约；
- 复用 `DefinitionModelValidator` 做保存前结构基础校验；
- 在定义修改类动作中接入数据库幂等处理；
- 与 B 线约定并预留定义变更后的缓存失效接口或事件点；
- 在 `saveGraph`、`copyDefinition`、`deleteDefinition` 中统一处理 `formFields`、`attachmentConfigs` 的保存、复制、删除事务边界；
- 建立入金申请流程定义验收数据和测试。

A 线 M1 不再负责：

- 重新设计公共 Service/SPI/enums 契约；
- 重新设计运行时请求、运行时结果 DTO 或任务乐观锁契约；
- 实现流程实例启动、审批流转、历史任务归档、回调投递；
- 实现发布、激活、停用、归档、灰度发布的完整状态治理；
- 实现附件模板主数据的维护、启停、版本治理；M1 只在定义维度保存表单字段和附件配置绑定关系；
- 实现 REST Controller，除非后续明确 M1 要开放本地调试 API。

## M1 前置决策与已定结论

在进入编码前，A 必须完成以下决策，否则容易出现实现与契约冲突。当前 D1-D5 均已确认。

| 编号 | 决策项 | 当前代码现状 | M1 处理要求 |
| --- | --- | --- | --- |
| D1 | 定义管理幂等动作类型 | `ActionTypeEnum` 表达运行时/任务动作，定义管理动作需要独立语义 | 采用方案 A：新增 `DefinitionActionTypeEnum`；`process_operation_record.action_type` 继续存字符串，定义管理动作落库为 `DEFINITION_CREATE`、`DEFINITION_SAVE_GRAPH`、`DEFINITION_COPY`、`DEFINITION_DELETE` 等命名空间值 |
| D2 | `copyDefinition` 是否允许改 `processCode` | `CopyProcessDefinitionRequest.processCode` 注释允许为空时沿用原编码 | M1 确认默认沿用源定义 `processCode` 生成下一版本；`request.processCode` 暂不作为改编码入口，避免把复制版本和另存为新流程混在同一能力中 |
| D3 | `saveGraph` 是否保存定义期扩展数据 | 请求已含 `formFields`、`attachmentConfigs` | 采用统一事务保存：A 的 `saveGraph` 同时保存节点、连线、表单字段和附件配置绑定；复制、删除定义时同步复制或删除这些定义期扩展数据 |
| D4 | 删除口径 | 主文档写定义级关联删除，旧 M1 计划曾写仅删除草稿 | M1 确认实现定义级级联删除；删除前禁止删除 `ACTIVE` 定义，并补齐运行期子表、定义期扩展和日志保留测试 |
| D5 | 缓存失效接口 | 当前未见 B 线缓存失效组件 | A 先预留缓存失效接口或事件点；保存、复制、删除事务提交后触发，真实缓存实现由 B 线后续接入 |

推荐执行顺序：

```text
M1.0 代码基线复核与前置决策
  -> M1.1 定义期 Repository 与 RowMapper
  -> M1.2 定义管理映射器与基础校验
  -> M1.3 创建、详情、分页、节点查询
  -> M1.4 整图保存与结构校验
  -> M1.5 复制定义与版本分配
  -> M1.6 删除定义与扩展生命周期
  -> M1.7 幂等持久化、联调和验收测试
```

### M1.1 定义期 Repository 与 RowMapper

开发内容：

1. 新增 `ProcessDefinitionRepository`：
   - `findById`；
   - `findMaxVersionByProcessCode`；
   - `insert`；
   - `updateBasicInfo` 或 `touchUpdated`；
   - `deleteById`；
   - `countByQuery`；
   - `searchByQuery`；
   - `existsInstanceByDefinitionId`。
2. 新增 `ProcessNodeRepository`：
   - `findByDefinitionId`，排序为 `sort_order, node_code`；
   - `batchInsert`；
   - `deleteByDefinitionId`。
3. 新增 `ProcessEdgeRepository`：
   - `findByDefinitionId`，排序为 `sort_order, edge_code`；
   - `batchInsert`；
   - `deleteByDefinitionId`。
4. RowMapper 统一处理：
   - SQLite 文本时间到 `LocalDateTime`；
   - `default_edge` 的 0/1 到 `Boolean`；
   - JSON 字段保持 `String`；
   - 空值字段不做业务推断。
5. Repository 只负责持久化，不做发布校验、权限判断或运行时解析。

产出：

- 三个 Repository；
- RowMapper 或 Mapper 工具；
- Repository 集成测试。

完成标准：

- 能插入、读取、删除定义、节点、连线；
- 唯一约束实际生效：`process_code + version`、定义内 `node_code`、定义内 `edge_code`；
- 查询顺序稳定；
- Repository 测试基于 SQLite 内存库或临时库运行。

### M1.3 创建、详情、分页、节点查询

开发内容：

1. 实现 `createDefinition(CreateProcessDefinitionRequest request)`：
   - 校验请求；
   - 在事务内按 `processCode` 查询最大版本；
   - 分配下一版本；
   - 插入 `DRAFT + INACTIVE + OFF` 定义；
   - `createdBy`、`updatedBy` 使用 `operatorUserId`；
   - 接入幂等记录。
2. 实现 `getDefinition(String definitionId)`：
   - 查询定义基本信息；
   - 查询并排序节点、连线；
   - 装配表单字段和附件配置绑定数据；
   - 返回 `ProcessDefinitionDetailDTO`。
3. 实现 `searchDefinitions(ProcessDefinitionQuery query)`：
   - 支持流程编码、名称关键字、系统编码、定义状态、激活状态、灰度状态；
   - 默认页码和页大小；
   - 排序为 `updated_at DESC, process_code ASC, version DESC`。
4. 实现 `listNodes(String definitionId)`：
   - 只返回排序后的节点；
   - 不加载连线和扩展。

产出：

- 定义创建、详情、分页、节点查询服务；
- 创建版本分配测试；
- 查询排序测试。

完成标准：

- 首次创建同一 `processCode` 得到版本 1；
- 再次创建同一 `processCode` 得到版本递增；
- 新定义状态固定为 `DRAFT + INACTIVE + OFF`；
- 详情查询返回节点和连线；
- 分页查询筛选与排序稳定；
- 相同 `operationId`、相同请求重放返回首次结果。

### M1.4 整图保存与结构校验

开发内容：

1. 实现 `saveGraph(String definitionId, SaveProcessGraphRequest request)`：
   - 查询定义；
   - 校验定义处于 `DRAFT + INACTIVE + OFF`；
   - 校验节点编码、连线编码在请求内不重复；
   - 校验连线起点和终点均存在于节点集合；
   - 校验节点类型、审批人规则、多实例模式符合当前 enum 和 DDL；
   - 复用 `DefinitionModelValidator` 做基础结构校验。
2. 在同一事务内全量替换核心流程图：
   - 删除旧连线；
   - 删除旧节点；
   - 插入新节点；
   - 插入新连线；
   - 更新定义 `updated_by`、`updated_at`；
   - 同步全量替换 `formFields` 和 `attachmentConfigs`。
3. 失败时整体回滚，旧图仍可查询。
4. 事务提交后触发 B 线缓存失效接口或事件点；事务失败不得触发。

产出：

- 整图保存服务；
- 保存前结构校验；
- 表单字段和附件配置绑定的事务内保存能力；
- 事务回滚测试；
- 入金申请 5 节点 4 连线保存测试。

完成标准：

- 入金申请 `start -> apply -> manager -> finance -> end` 可保存和读取；
- 节点、连线排序稳定；
- 连线引用不存在节点时失败；
- 插入连线失败时旧节点和旧连线不丢失；
- 表单字段或附件配置保存失败时，节点和连线替换也整体回滚；
- 非编辑态定义不可保存；
- 相同 `operationId` 重放不重复写入。

### M1.5 复制定义与版本分配

开发内容：

1. 实现 `copyDefinition(String definitionId, CopyProcessDefinitionRequest request)`：
   - 加载源定义、节点、连线快照；
   - 目标 `processCode` 固定沿用源定义 `processCode`；
   - 在事务内查询源 `processCode` 最大版本；
   - 创建下一版本草稿；
   - 复制节点、连线，重建数据库主键，保留业务编码；
   - 复制表单字段和附件配置绑定，重建数据库主键，保持业务编码；
   - 接入幂等记录。
2. `CopyProcessDefinitionRequest.processCode` 在 M1 不作为改编码入口；若后续需要另存为新流程，单独新增能力或评审扩展语义。
3. 复制不继承源定义的激活、灰度、归档信息。
4. 版本唯一键冲突时整体回滚，必要时有限重试。
5. 事务提交后触发目标定义缓存失效事件点。

产出：

- 定义复制服务；
- 版本分配工具；
- 复制集成测试。

完成标准：

- 复制后目标定义为 `DRAFT + INACTIVE + OFF`；
- `processCode` 沿用源定义，`version` 递增；
- 新旧定义主键不同，节点和连线主键不同；
- 节点编码、连线编码和配置保持一致；
- 表单字段或附件配置复制失败时目标定义、节点、连线整体回滚；
- 同一 `operationId` 重放不产生新版本。

### M1.6 删除定义与扩展生命周期

开发内容：

1. 按 D4 决策实现定义级级联删除。
2. 删除前校验：
   - 禁止删除 `activation_status = ACTIVE` 的定义；
   - 归档、停用、草稿定义可删除；
   - `operationId`、`operatorUserId` 必须非空。
3. 在同一事务内按依赖顺序删除：
   - 定义期扩展数据，包含表单字段和附件配置绑定；
   - 附件记录、已阅记录、历史任务、活动任务、任务组、提醒、告警等运行期子表；
   - 清空审计日志、回调日志的实例外键引用；
   - 流程实例；
   - 连线、节点、定义；
   - 写入或更新幂等结果。
4. 审计日志、回调日志由 Service 显式清空 `instance_id` 引用后保留；`process_operation_record` 按幂等保留期保留，不因定义删除同步删除。
5. 删除失败必须整体回滚，不留下半删定义或半删实例。
6. 删除事务提交后触发 B 线缓存失效事件点。

产出：

- 删除定义服务；
- 级联删除策略说明；
- 删除集成测试。

完成标准：

- 删除策略与 D4 结论一致，且覆盖运行期子表；
- 删除失败不留下半删数据；
- 表单字段或附件配置删除失败时整体回滚；
- 同一 `operationId` 重放返回稳定结果；
- `ACTIVE` 定义不能被删除；
- 审计、回调、幂等记录保留策略与 DDL 和文档一致。

### M1.7 幂等持久化、联调和验收测试

开发内容：

1. 将 `IdempotencyAcceptanceBaselineTest` 的内存语义落成数据库组件：
   - begin；
   - replay success；
   - replay failed；
   - conflict；
   - processing lease；
   - mark success；
   - mark failed；
   - rollback 后可重试。

3. 与 B 线联调：
   - 详情读取满足发布校验和缓存需要；

   - `formFields`、`attachmentConfigs` 由 `saveGraph` 统一保存；

## 风险与处理

| 风险 | 处理 |
| --- | --- |
| 已有公共契约与旧 M1 文档不一致 | 以当前已合入代码为准，M1 文档只保留实现任务，不再要求 A 重新冻结公共契约 |
| 定义管理幂等缺少动作类型 | D1 已按方案 A 固化：定义动作使用 `DefinitionActionTypeEnum`，落库为 `DEFINITION_*` 命名空间值，避免复用运行时动作 |
| `SaveProcessGraphRequest` 同时包含节点、连线和定义期扩展 | D3 已确认统一事务保存；实现时必须覆盖表单字段和附件配置绑定，禁止只保存节点/连线后静默丢弃扩展字段 |
| 删除口径过大导致误删运行数据 | M1 已确认实现级联删除；必须禁止删除 `ACTIVE` 定义，并用运行期子表测试覆盖删除顺序和回滚 |
| 版本分配并发冲突 | 写事务内查询最大版本，唯一索引兜底，冲突后有限重试 |
| 整图保存覆盖他人编辑 | 当前模型没有定义级 `lock_version`；M1 可先不解决协同编辑，后续如需要再补模型 |
| 缓存失效接口未落地 | A 先预留事务提交后的缓存失效接口或事件点，B 线接入后再补真实缓存实现 |
