# 实习生A M6 技术实现说明

更新时间：2026-07-28

## 本次完成范围

- `RuntimeNodeAdvancer` 已按 `multiInstanceMode=OR_SIGN` 创建运行时任务组和多条候选人待办。

- 或签任务组复用 `process_task_group`，并在并行分支上下文中将外层 `taskGroupId/branchKey` 保存到 `parentGroupId/parentBranchKey`。

- `TaskGroupRepository` 已新增 `completeOrSignGroup`，以 `group_type=OR_SIGN`、`group_status=ACTIVE` 和 `lock_version` 做一次性 CAS。

- `ActiveTaskRepository` 已新增 `findOpenByTaskGroupId`，用于读取同组内除赢家任务外仍开放的 `ACTIVE/CLAIMED` 待办。

- `DefaultProcessRuntimeService.approve` 已识别 `OR_SIGN` 任务组，完成赢家任务、完成任务组、取消同组剩余待办并归档，再按父级上下文继续推进。

- 节点配置为 `OR_SIGN` 的任务审批时不再允许任务组缺失或非 `OR_SIGN` 类型回落到普通审批路径。任务组缺失返回 `FLOW_TASK_GROUP_NOT_FOUND`，非或签任务组返回 `FLOW_TASK_GROUP_STATUS_INVALID`，避免绕过任务组 CAS 唯一推进语义；普通并行分支任务仍保留原 `taskGroupId/branchKey` 推进链路。

- `TaskActionResult` 公共结构保持不变，完成任务和被取消任务均通过 `archivedTasks` 返回；被取消任务使用 `ActionTypeEnum.CANCEL`。

## 边界保持

- 未实现 `COUNTERSIGN` 会签闭环，不修改 `incrementCompletedCount` 的会签语义。

- 未放开驳回、撤回、转办、加签、直送等增强动作对分组任务的限制。

- 未新增 REST 接口、DTO 字段、数据库表或多数据库适配。

- 未改变条件表达式语法范围和排他网关既有路由实现。
