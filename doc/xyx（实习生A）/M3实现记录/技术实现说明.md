技术基线：Java 8、Spring Boot 2.7.18、Spring JDBC、SQLite

## 1. 实现边界

本阶段在 `platform-core` 内实现流程定义的非灰度生命周期治理：发布、激活、停用、归档。实现与《流程平台技术路线_v5.2》《流程平台设计与接口文档_v4》的版本治理方向保持一致，但根据当前明确范围暂不实现灰度发布。

已实现：

- `publish`：草稿定义发布为 `PUBLISHED + INACTIVE + OFF`。
- `activate`：已发布未激活全量版本激活为 `PUBLISHED + ACTIVE + OFF`。
- `deactivate`：已激活全量版本停用为 `PUBLISHED + INACTIVE + OFF`。
- `archive`：已发布未激活全量版本归档为 `ARCHIVED + INACTIVE + OFF`。
- 生命周期操作幂等、审计日志和缓存失效。

未实现：

- `enableGray`。
- `disableGray`。
- 灰度规则 JSON 校验、灰度命中和灰度版本选择。
- `platform-starter` 自动装配。
- REST 调试入口。

## 3. 状态流转

M3 当前只支持全量版本生命周期，灰度状态必须为 `OFF`。

| 操作 | 前置状态 | 目标状态 | 说明 |
| --- | --- | --- | --- |
| 发布 | `DRAFT + INACTIVE + OFF` | `PUBLISHED + INACTIVE + OFF` | 发布前必须通过流程模型校验 |
| 激活 | `PUBLISHED + INACTIVE + OFF` | `PUBLISHED + ACTIVE + OFF` | 激活前停用同流程编码下其他全量激活版本 |
| 停用 | `PUBLISHED + ACTIVE + OFF` | `PUBLISHED + INACTIVE + OFF` | 不删除定义，不影响已绑定该定义的实例 |
| 归档 | `PUBLISHED + INACTIVE + OFF` | `ARCHIVED + INACTIVE + OFF` | 记录归档人和归档时间，归档后不可再次激活 |

如果当前定义 `gray_status != OFF`，生命周期操作会拒绝执行。该限制避免 M3 非灰度逻辑误处理灰度版本。

## 4. Service 实现

默认实现类为 `DefaultProcessDefinitionService`。

### 4.1 发布

`publish(DefinitionOperationRequest request)` 的处理顺序：

1. 校验 `definitionId`、`operatorUserId`、`operationId`。
2. 使用 `DefinitionActionTypeEnum.PUBLISH` 生成动作类型。
3. 根据动作、定义 ID 和操作人生成幂等请求摘要。
4. 调用 `OperationIdempotencyService.beginOrReplay`。
5. 幂等成功重放时读取首次结果对应的定义并返回。
6. 首次执行时读取定义，要求 `gray_status = OFF`。
7. 调用 `validateForPublish(definitionId)` 执行发布前校验。
8. 调用 Repository 条件更新发布状态。
9. 写审计日志、标记幂等成功、注册缓存失效。

发布校验失败时直接抛出 `DefinitionValidationException`，不会写入成功幂等结果，也不会写审计日志。

### 4.2 激活

`activate(DefinitionOperationRequest request)` 的处理顺序：

1. 校验请求并进入生命周期幂等流程。
2. 读取目标定义，要求 `PUBLISHED + INACTIVE + OFF`。
3. 查询当前同 `processCode` 下的旧全量激活版本。
4. 在同一事务内先停用旧全量版本，再激活目标定义。
5. 写审计日志并标记幂等成功。
6. 失效目标定义缓存；如果存在旧激活版本，也同步失效旧定义缓存。

SQLite schema 中的部分唯一索引 `uk_process_definition_active_full` 作为并发兜底，保证同一流程编码下不会同时存在多个 `PUBLISHED + ACTIVE + OFF` 全量版本。

### 4.3 停用

`deactivate(DefinitionOperationRequest request)` 要求目标定义当前为 `PUBLISHED + ACTIVE + OFF`。停用只修改 `activation_status`，不删除定义图、表单字段、附件配置或运行数据。运行中实例已经固化 `definitionId`，后续流转不应因定义停用而切换版本。

### 4.4 归档

`archive(DefinitionOperationRequest request)` 要求目标定义当前为 `PUBLISHED + INACTIVE + OFF`。归档时写入：

- `definition_status = ARCHIVED`
- `activation_status = INACTIVE`
- `gray_status = OFF`
- `archived_by`
- `archived_at`
- `updated_by`
- `updated_at`

归档后的定义不满足激活条件，因此不能再次激活；如需再次使用，应复制出新草稿版本。

## 5. Repository 实现

`ProcessDefinitionRepository` 新增生命周期持久化方法：

| 方法 | 作用 |
| --- | --- |
| `publish` | 将草稿定义发布为未激活版本 |
| `activateFull` | 激活已发布未激活的全量版本 |
| `deactivate` | 停用已发布且激活的全量版本 |
| `deactivateActiveFullByProcessCode` | 停用同一流程编码下除目标定义外的旧全量激活版本 |
| `archive` | 归档已发布未激活的全量版本 |
| `insertAuditLog` | 写入生命周期审计日志 |

这些方法只负责 SQL 执行和受影响行数返回，不做业务判断。Service 根据受影响行数判断状态是否已经被其他请求改变。

## 6. 幂等设计

生命周期操作复用 `OperationIdempotencyService`，不新增第二套幂等组件。动作类型来自 `DefinitionActionTypeEnum`，落库时仍使用定义动作命名空间：

- `DEFINITION_PUBLISH`
- `DEFINITION_ACTIVATE`
- `DEFINITION_DEACTIVATE`
- `DEFINITION_ARCHIVE`

请求摘要由以下字段计算：

- 生命周期动作；
- `definitionId`；
- `operatorUserId`。

幂等语义：

- 同一 `operationId`、同一动作和同一请求摘要：成功后返回首次结果。
- 同一 `operationId`、不同动作或不同请求摘要：返回幂等冲突。
- 同一 `operationId` 仍处于处理租约内：返回处理中语义。
- 处理租约过期：允许后续请求接管。

## 7. 审计日志

发布、激活、停用、归档成功后写入 `process_audit_log`：

- `target_type = DEFINITION`
- `target_id = definitionId`
- `action_type = DEFINITION_*`
- `operator_id = operatorUserId`
- `operation_id = request.operationId`
- `detail_json` 记录操作后的 `definitionStatus`、`activationStatus`、`grayStatus`

灰度接口未实现，因此不会写灰度开启或关闭审计日志。

## 8. 缓存失效

生命周期操作成功后调用现有缓存失效机制：

```java
registerGraphCacheInvalidation(definitionId);
```

激活操作可能同时改变旧全量激活版本和目标版本，因此会额外失效旧激活定义的缓存。缓存失效注册在事务提交后执行；如果没有事务同步上下文，则立即执行。

## 9. 并发处理

当前并发处理是轻量级状态一致性设计：

- 相同 `operationId` 的并发重试由 `process_operation_record.operation_id` 唯一键和幂等服务处理。
- 同一定义的重复发布、停用、归档由 Repository 条件更新处理。
- 同流程编码全量激活唯一性由 SQLite 部分唯一索引兜底。

限制：

- 当前没有定义级 `lock_version`。
- 不同 `operationId` 并发激活同一流程编码下的不同版本时，最终不会出现两个 active，但可能形成后写覆盖先写的业务效果。
- 若后续要求严格串行化，应补充定义级乐观锁或流程编码级锁。

## 10. 灰度边界

`enableGray` 和 `disableGray` 当前固定抛出：

```text
UnsupportedOperationException
```

异常信息明确说明灰度发布不在本次 M3 实现范围。这样既保留设计文档中的接口形态，也避免调用方误以为灰度已生效。

## 12. 与 B/C 线协作点

提供给 B 线：

- 新实例启动时可按 `processCode` 查询 `PUBLISHED + ACTIVE + OFF` 的全量版本。
- 定义停用后，已有实例仍应按实例固化的 `definitionId` 继续加载原定义。
- 激活、停用、归档后缓存会按定义 ID 失效。

提供给 C 线：

- A 线不实现 starter 自动装配。
- C 线后续在 starter 中装配默认实现时，应复用 `DefaultProcessDefinitionService`、Repository、幂等服务和缓存，不重复实现生命周期逻辑。
- C 线集成测试可直接覆盖发布、激活、发起流程的串联验收。
