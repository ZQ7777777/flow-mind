## 1. 本阶段决策

M5 阶段 A 线只负责增强动作相关的定义配置冻结和发布期校验，不负责会签/或签真实运行时闭环。

已确认两项关键决策：

- 会签/或签在 M5 只要求配置冻结，运行时任务组创建、抢占、计数推进和完整闭环放到 M6。
- `listenerConfig` 继续承载 `taskActionRules`，不新增 `action_rule_config` 字段，不新增动作规则表。

`taskActionRules` 固定放在节点 `listenerConfig` JSON 根对象下，用于 B 线驳回、直送动作读取：

```json
{
  "taskActionRules": {
    "reject": {
      "enabled": true,
      "targetNodeCodes": ["apply"]
    },
    "directSend": {
      "enabled": true,
      "targetMode": "REJECT_SOURCE"
    }
  }
}
```

## 2. A 线范围

A 线 M5 交付范围：

- 节点监听配置契约冻结。
- 条件表达式配置契约冻结。
- 会签/或签节点配置契约冻结。
- 驳回/直送规则配置契约冻结。
- 流程定义保存、复制、详情查询中的配置字段保真。
- 发布前模型校验覆盖上述配置。
- 为 B 线提供稳定的规则读取边界，为 C 线提供可查询、可审计的配置语义。

A 线 M5 不交付以下内容：

- 不实现驳回、撤回、转办、加签的任务 CAS、历史归档、回调和事务编排，这些属于 B 线。
- 不实现委托代办、认领、取消认领、审计日志查询、已阅、提醒和回归测试总收口，这些属于 C 线。
- 不实现 OR_SIGN、COUNTERSIGN 的运行时任务组闭环，M5 只保证配置可保存、可发布、可被运行时读取。
- 不新增数据库表，不新增多数据库适配，不引入 Spring Boot 3.x、Jakarta 或 Java 9+ API。

## 3. 当前代码基线

当前已有可复用基础：

- `ProcessNodeDTO.multiInstanceMode` 已存在，可表达 `SINGLE`、`OR_SIGN`、`COUNTERSIGN`。
- `ProcessNodeDTO.listenerConfig` 已存在，可继续承载节点监听和动作规则 JSON。
- `ProcessEdgeDTO.conditionExpression` 已存在，可表达条件分支出线表达式。
- SQLite `process_node` 已有 `multi_instance_mode`、`listener_config`，`process_edge` 已有 `condition_expression`。
- `RuntimeNodeConfigReader` 已能解析节点 JSON 配置。
- `SimpleConditionExpressionEvaluator` 已提供受限单变量比较表达式能力。
- `RuntimeNodeAdvancer` 已能在排他网关按 `conditionExpression` 选择出线。
- `EnhancedTaskActionCoordinator` 已按 `listenerConfig.taskActionRules.reject/directSend` 读取驳回和直送规则。

当前需要 A 线补齐的缺口：

- `taskActionRules` JSON 结构尚未形成独立配置契约和发布期校验。
- 条件表达式语法主要在运行时失败，缺少发布前配置校验。
- 网关节点与 `multiInstanceMode` 默认值存在边界风险：数据库默认 `SINGLE`，但发布校验不应把非用户任务上的默认 `SINGLE` 误判为非法多人配置。
- 会签/或签目前只保留候选人集合语义，缺少“配置冻结但运行时闭环留到 M6”的显式测试和文档说明。

### M5-A.1 冻结节点监听和动作规则契约

开发内容：

- 更新 `ProcessNodeDTO.listenerConfig` 字段 Javadoc，明确 JSON 对象格式。
- 固化 `listenerConfig.taskActionRules.reject`：
  - `enabled`：布尔值，是否允许从当前节点驳回。
  - `targetNodeCodes`：字符串数组，允许驳回到的用户任务节点编码。
- 固化 `listenerConfig.taskActionRules.directSend`：
  - `enabled`：布尔值，是否允许从当前返工节点直送。
  - `targetMode`：固定取值 `REJECT_SOURCE`，表示只能直送回可信驳回来源节点。
- 保留 `listenerConfig` 未来承载普通节点监听的能力，不把 `taskActionRules` 独立拆表。

完成标准：

- DTO Javadoc 能说明字段业务含义、JSON 格式和典型取值。
- 配置契约与 B 线 `EnhancedTaskActionCoordinator` 当前读取路径一致。

### M5-A.2 增加动作规则读取与校验组件

开发内容：

- 新增轻量配置读取组件，建议命名为 `TaskActionRuleConfigReader`。
- 读取源为 `ProcessNodeDTO.listenerConfig`。
- 输出只包含规则语义，不暴露 Jackson 原始 Map 给动作编排层。
- 支持读取：
  - 当前节点是否允许驳回；
  - 允许驳回目标节点编码集合；
  - 当前节点是否允许直送；
  - 直送目标模式是否为 `REJECT_SOURCE`。
- 非法 JSON、字段类型错误、未知 `targetMode` 使用稳定错误码或发布校验 issue 表达。

完成标准：

- B 线动作实现可以复用该读取组件，减少散落解析 `listenerConfig`。
- 空 `listenerConfig` 表示未启用增强动作规则。
- 不新增公共 Service 接口。

### M5-A.3 补发布前模型校验

开发内容：

- 在 `DefinitionModelValidator` 中补 M5 配置校验。
- 用户任务节点允许 `SINGLE`、`OR_SIGN`、`COUNTERSIGN`。
- 非用户任务节点不允许显式配置 `OR_SIGN`、`COUNTERSIGN`；数据库默认的 `SINGLE` 按“无多人配置”处理。
- `listenerConfig` 如非空必须是 JSON 对象。

完成标准：

## 5. 与 B/C 线协作点

提供给 B 线：

- 驳回和直送只读取 `listenerConfig.taskActionRules`。
- `reject.targetNodeCodes` 是定义期白名单，动作执行时仍需按当前实例固化定义校验。
- `directSend.targetMode=REJECT_SOURCE` 表示不能把直送实现成任意节点跳转。
- A 线不承担任务 CAS、历史归档、回调和事务编排。

提供给 C 线：

- 查询、审计、回调展示如需显示增强动作规则，统一从节点 `listenerConfig` 读取。
- `OR_SIGN/COUNTERSIGN` 在 M5 是配置态能力，读侧可以展示配置，但不应声明运行时闭环已完成。
- 已阅、提醒、审计日志查询和回归测试总收口仍由 C 线负责。

## 6. 验收标准

- `listenerConfig.taskActionRules` 结构冻结，并有 Javadoc 和测试覆盖。
- `conditionExpression` 支持范围冻结，并能发布前校验非法表达式。
- `OR_SIGN/COUNTERSIGN` 可作为用户任务配置保存、查询、复制和发布校验通过。
- 非用户任务的多人审批配置边界清晰，默认 `SINGLE` 不阻断网关发布。
- 驳回/直送规则只通过 `listenerConfig` 承载，不新增数据库字段和表。
- A 线改动不接管 B 线动作执行，也不接管 C 线认领、委托、审计、已阅和提醒。
- 在 `platform` 目录执行 `mvn -q test` 通过。

## 8. 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| `listenerConfig` 同时承载监听和动作规则，后续可能变复杂 | M5 固定 `taskActionRules` 命名空间，普通监听配置保留在其他键下 |
| 条件表达式发布期校验与运行时求值不一致 | 复用同一语法解析逻辑，发布期只验语法，运行时验变量值 |
| 数据库默认 `multi_instance_mode='SINGLE'` 影响网关校验 | 将非用户任务的 `SINGLE` 视为无多人配置，显式 `OR_SIGN/COUNTERSIGN` 才拒绝 |
| B 线已直接解析 `listenerConfig` Map | A 线提供统一 reader，B 线按最小改动接入 |
| M5 与 M6 会签/或签边界混淆 | 本文件和测试明确 M5 只冻结配置，M6 再实现运行时任务组闭环 |
