- 组织架构查询 SPI。

- `UserDTO` 的部门、角色和有效状态字段。
- `USER`、`STARTER`、`DEPARTMENT`、`ROLE`、`ROLE_IN_DEPARTMENT`、`APPROVER_EXPRESSION` 六类规则解析。
- 审批人去重、稳定排序和有效用户过滤。
- `SINGLE`、`OR_SIGN`、`COUNTERSIGN` 候选人集合语义在解析入口保留。

## 4. 当前可验收能力

- 用户任务节点的审批人规则可以通过统一 `ApproverResolver` 解析。
- `USER` 规则按 `userIds` 查询用户。
- `STARTER` 规则按 `starterUserId` 查询用户。
- `DEPARTMENT` 规则按部门查询用户。
- `ROLE` 规则按角色查询用户。
- `ROLE_IN_DEPARTMENT` 规则按角色和部门交集查询用户。
- `ROLE_IN_DEPARTMENT` 缺少 `departmentId` 时使用 `starterDeptId`。
- `APPROVER_EXPRESSION` 支持受限函数表达式。
- 表达式只能读取字符串字面量、`starterUserId`、`starterDeptId` 和 `variables.xxx`。
- 表达式解析结果仍通过 `OrganizationProvider` 查询用户。
- 解析结果会过滤 `active = false` 的用户。
- 解析结果按 `userId` 去重并稳定排序。
- 返回结果保留用户名称、部门、角色和有效状态字段。
- `ApproverResolveRequest` 包含 `multiInstanceMode`。
- `RuntimeNodeAdvancer` 创建用户任务前调用审批人解析。
- `OR_SIGN`、`COUNTERSIGN` 不再被解析入口提前拒绝。
- 审批人为空或解析异常时，不创建无候选人的活动任务。

## 6. 表达式能力说明

当前 `APPROVER_EXPRESSION` 支持以下函数：

- `departmentManager(starterDeptId)`
- `roleInDepartment("roleCode", starterDeptId)`
- `role("roleCode")`
- `department(starterDeptId)`
- `user(starterUserId)`

表达式限制：

- 不支持脚本执行。
- 不支持反射、类加载、系统属性、文件或网络访问。
- 不支持任意函数调用。
- 不支持括号嵌套。
- 不支持读取白名单之外的上下文。

该实现满足“只能读取允许上下文，不允许任意代码执行”的 M4 收口要求。

## 11. M4 运行时自动接线补充（2026-07-27）

本次补充将 A 线的 `DefaultApproverResolver` 接入实际运行时调用链，链路为：

`DefaultProcessRuntimeService` → `RuntimeNodeAdvancer` → `ApproverResolver` → `DefaultApproverResolver` → `OrganizationProvider`。

- `platform-starter` 在宿主提供 `OrganizationProvider`、且未显式提供 `ApproverResolver` 时，自动注册 `DefaultApproverResolver`；宿主自定义 `ApproverResolver` 保持优先。
- 独立运行配置同步改为提供最小 `OrganizationProvider` 并复用 `DefaultApproverResolver`，不再维护只支持部分规则的 lambda 解析器。
- 独立调试组织 SPI 仅识别内置的销售、经理、财务部门和角色；未知部门、角色或角色-部门组合返回空结果，使运行时统一报 `FLOW_APPROVER_RESOLVE_FAILED`，不会错误创建候选任务。
- `DefaultApproverResolver` 按用户 ID 去重并排序是既有 M4 契约，独立运行环境的 `USER` 规则结果也遵循该统一行为。
