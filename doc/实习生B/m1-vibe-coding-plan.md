# 实习生 B：M1 流程定义运行前校验与缓存 Vibe Coding 计划

## 产物与边界

新建 `doc/实习生B/m1-vibe-coding-plan.md`，作为 M1 专项编码计划；不修改 M0 专项计划和现有总计划。

M1 的 B 线只负责：

1. 读取 A/C 提供的完整流程定义数据；
2. 将定义、节点、连线和扩展配置解析为不可变运行时图快照；
3. 实现发布前运行语义校验；
4. 缓存已发布且激活的运行时快照，并在定义变化提交后失效缓存；
5. 为上述能力编写单元测试与跨线集成测试。

M1 不实现以下内容：

- A 负责的流程定义 CRUD、复制、版本分配、节点/连线持久化、发布/激活/停用/归档状态变更；
- C 负责的表单字段、附件模板与附件配置持久化；
- M2 的实例启动、节点推进、任务创建、审批人解析、幂等执行和乐观锁更新；
- 条件表达式求值、并行/会签/或签运行、Repository 或 SQLite 专有 SQL；
- 重复的公共 DTO、枚举、Service、SPI 或兼容别名。

流程图设计数据必须完整保留。依据需求文档，至少包括节点、连线、节点坐标和节点顺序；依据 v4，还需保留节点/网关配置、连线条件、默认出线和连线顺序。坐标仅用于设计器展示，不参与运行时路由判断。

## 基线与优先级

发生描述差异时按以下优先级执行：

1. **具体业务能力和验收语义**：`doc/rebuild-functional-requirements-optimized.md`；
2. **数据模型、字段、接口和校验细则**：`doc/流程平台设计与接口文档_v4.md`；
3. **阶段分工**：`doc/流程平台技术路线_v5.2.md`；
4. **B 线总体顺序**：`doc/实习生B/plan.md`。

M1 必须满足的需求基线：

- 可读取和解析包含开始节点、用户任务、结束节点和网关节点的流程图；
- 流程图包含节点、连线、节点坐标、节点顺序等设计数据；
- 发布前能够拦截开始/结束节点缺失、节点孤立、连线不完整、用户任务未配置审批人等明显错误；
- 能识别审批人规则、多人处理模式、监听配置、条件表达式、表单字段和附件配置；
- 只有已发布且激活的流程定义才能进入运行时缓存并供后续实例启动使用；
- 流程定义保存、发布、激活、停用、归档和删除后，旧运行时快照不能继续被使用。

## 目标结构

具体包名在 B1.1 与 A/C 最终类型对齐后冻结，建议将 B 自有实现放在 `com.flowmind.platform.runtime.definition` 下，不向 `api` 包复制 A/C 的公共类型。

```text
platform-core/src/main/java/com/flowmind/platform
├── api/                              # 复用 A/B/C 已冻结的公共类型
└── runtime/definition/
    ├── graph/                        # 不可变运行时图、索引和解析器
    ├── validation/                   # 发布前校验规则及聚合器
    ├── cache/                        # 运行时快照缓存与失效
    └── port/                         # 读取定义/扩展配置的最小端口

platform-core/src/test/java/com/flowmind/platform/runtime/definition
├── graph/
├── validation/
├── cache/
└── integration/
```

推荐的数据流：

```text
A 的定义/节点/连线数据 ─┐
                         ├─> 只读加载端口 -> 完整定义数据 -> 校验器
C 的表单/附件配置数据 ──┘                           │
                                                    ├─ 校验问题列表
                                                    └─ 解析器 -> 不可变快照 -> 缓存
```

## 并行与等待

M1 编码必须建立在 B0.5 已完成、公共 DTO/枚举/Service 已冻结的 `develop` 基线上。不得在旧的 M0 功能分支上直接叠加 M1。

建议从最新 `develop` 新建：

```powershell
git switch develop
git pull --ff-only origin develop
git switch -c feature/m1-b-definition-runtime
```

以下是强制依赖点：

| 依赖方 | M1 最小交付 | B 的处理 |
| --- | --- | --- |
| A | 定义、节点、连线的正式 DTO/枚举；可按定义 ID 读取完整流程图的接口或适配实现；定义状态与激活状态；变更提交后的缓存失效协作点 | B 不复制 A 的定义模型；通过最小只读端口消费数据 |
| C | 表单字段 DTO、附件模板/附件配置 DTO；可按定义 ID 读取发布校验所需扩展配置的接口或适配实现 | C 未就绪前先完成纯图校验；扩展校验与最终联合测试等待 C |

B1.1 可以与 A/C 并行评审接口，但在正式类型未合入前不得创建临时公共类型。纯算法测试允许使用测试目录内的构建器或夹具，不得把测试替代类型放入生产代码。

## 统一编码与审查规则

- Java 8、Spring Boot 2.7.18；禁止 Java 9+ API、Lombok 和 `record`。
- 运行时图快照对外只读；构造时复制集合，访问时不得暴露可修改内部集合。
- 节点和连线索引使用稳定、可预测的顺序；同一输入必须得到同一校验问题顺序。
- 校验规则只报告问题，不修改 A/C 的持久化对象，也不隐式发布或激活定义。
- 条件表达式在 M1 只校验“应配置/不应配置”和基础非空；实际求值留到后续阶段。
- 每个微任务完成后：补齐单元测试，执行计划规定的 Maven 命令，委派子 agent 进行只读代码审查；修复问题并重新测试后再提交。
- 每次提交只包含当前微任务文件，不夹带其他实习生或用户尚未提交的修改。

## 微任务与编码提示词

### B1.1：冻结运行时定义读取契约

与 A/C 对齐一个且仅一个完整定义读取边界。B 只定义运行时所需的最小端口和不可变快照输入结构；如果 A/C 已提供等价正式类型，直接复用，不创建别名。

完整输入至少包含：

- 定义：定义 ID、流程编码、版本、发布状态、激活状态；
- 节点：编码、名称、节点类型、配对网关编码、审批人规则类型/配置、多人模式、监听/超时/提醒配置、`positionX`、`positionY`、`sortOrder`；
- 连线：编码、来源节点、目标节点、条件表达式、默认出线标识、`sortOrder`；
- C 的扩展：表单字段编码，以及附件配置组、附件模板编码、适用节点和生效状态等发布校验所需字段。

端口只负责读取，不允许 B 直接依赖 A/C Repository 或在端口中写数据库。

提示词：

“在 `platform-core` 为 B 的 M1 定义最小只读运行时定义加载边界。优先复用 A/C 已合入的正式 DTO 和枚举；不得创建重复公共类型。输入必须完整保留节点、连线、节点坐标、节点顺序、连线顺序与发布校验所需的表单/附件配置。只实现接口、不可变输入结构和契约测试，不实现缓存、校验规则或持久化。”

测试与完成条件：

- 验证完整定义可以表达节点、连线、坐标和顺序；
- 验证空集合、可选配置和正式枚举类型的 Java 8 构造方式；
- 验证快照输入集合不暴露可修改内部状态；
- 执行 `mvn -q -pl platform/platform-core -am test`；
- 子 agent 审查类型是否与 A/C 重复、是否越过只读边界；通过后提交 B1.1。

建议提交：`feat: add runtime definition read contract`

### B1.2：解析不可变运行时流程图

实现流程图解析器，将完整定义数据转换为不可变运行时图快照。解析阶段建立：

- `nodeCode -> node` 索引；
- `edgeCode -> edge` 索引；
- 节点入线和出线邻接表；
- 按 `sortOrder`、编码进行稳定排序的节点和连线视图；
- 开始节点、结束节点和网关节点的快速读取视图。

解析器必须保留节点坐标和设计顺序，但运行时出线选择只使用连线 `sortOrder`，不能使用画布坐标决定流程方向。

提示词：

“实现 Java 8 的不可变运行时流程图解析器。根据正式定义、节点和连线类型建立节点/连线索引、入线/出线邻接表和稳定排序视图。完整保留 positionX、positionY、节点 sortOrder 和连线 sortOrder；禁止用坐标推断流程方向。解析器不访问数据库、不执行发布校验、不求值条件表达式。”

测试与完成条件：

- 使用通用流程夹具：开始节点 → 两个用户任务 → 结束节点；每个节点设置不同坐标和顺序；
- 打乱输入节点/连线顺序后，解析结果仍按规则稳定；
- 读取返回集合不可被调用方修改；
- 空图也能被解析为待校验快照，不在解析器中提前吞掉校验问题；
- 执行模块测试并完成子 agent 审查后提交 B1.2。

建议提交：`feat: parse immutable runtime definition graphs`

### B1.3：实现基础发布前校验

实现可组合的发布校验规则及问题聚合器，至少覆盖：

1. 存在且仅存在一个开始节点；
2. 至少存在一个结束节点；
3. 同一定义版本下节点编码、连线编码分别唯一；
4. 所有连线的来源和目标节点都存在；
5. 不存在孤立用户任务节点；
6. `START` 和 `USER_TASK` 只能有一条出线，需要分支时必须显式使用网关；
7. 用户任务必须配置审批人规则；
8. 网关不得配置审批人规则或多人处理模式。

校验问题使用 A 已冻结的 `ValidationResult`/问题类型；如果正式类型尚未合入，则本微任务等待，不创建临时公共返回对象。问题顺序按规则号、节点/连线顺序和编码保持稳定。

提示词：

“实现 B 的发布前基础图校验器，输入为 B1.2 的只读运行时图，输出使用 A 的正式 ValidationResult。每条规则独立、可单测，统一聚合全部问题而不是首错即停。不得修改流程图、发布定义、访问 Repository 或实现审批人解析。”

测试与完成条件：

- 每条规则至少包含一个通过和一个失败用例；
- 一个图同时违反多条规则时返回完整且顺序稳定的问题列表；
- 用户任务审批人配置只验证存在性和基本结构，不调用组织架构 SPI；
- 执行模块测试并完成子 agent 审查后提交 B1.3。

建议提交：`feat: validate publishable definition graphs`

### B1.4：实现条件与并行网关拓扑校验

补齐 v4 的网关规则：

- `EXCLUSIVE_GATEWAY` 至少两条出线、最多一条默认出线；非默认出线必须配置条件表达式；
- `PARALLEL_SPLIT_GATEWAY` 至少两条出线；出线不得配置条件表达式；必须配置存在且类型正确的配对汇聚网关；
- `PARALLEL_JOIN_GATEWAY` 至少两条入线且只能有一条出线；必须与分支网关双向配对；
- 并行分支网关的每条路径必须能到达其配对汇聚网关；
- 网关不会创建活动任务，因此不得被解析为长期停留的用户任务节点。

M1 只校验拓扑和表达式是否应存在，不执行表达式，不实现并行汇聚。

提示词：

“在发布校验器中增加 EXCLUSIVE_GATEWAY、PARALLEL_SPLIT_GATEWAY 和 PARALLEL_JOIN_GATEWAY 的拓扑规则。使用图遍历验证配对和分支可达性；遍历必须有 visited 集合避免环路。只报告完整、稳定的校验问题，不执行条件表达式或流程推进。”

测试与完成条件：

- 覆盖合法条件分支、缺少条件、多默认线、出线不足；
- 覆盖合法并行分支/汇聚、配对缺失、类型错误、单向配对、分支无法到达汇聚；
- 覆盖带环图，校验器必须有限结束；
- 执行模块测试并完成子 agent 审查后提交 B1.4。

建议提交：`feat: validate gateway topology`

### B1.5：实现表单与附件扩展配置校验

等待 C 的正式扩展配置读取能力后，补齐与发布相关的跨线规则：

1. 同一定义内表单字段编码不重复；
2. 同一流程定义附件配置组内附件模板编码绑定不重复；
3. 附件配置的适用节点必须存在；
4. 已生效附件配置不可原地修改；规则变化必须生成新的配置组；
5. 发布输入能够完整表达附件类型、数量、大小、适用节点和必填等需求配置，但 B 不负责持久化或运行时上传校验。

提示词：

“复用 C 的正式表单字段和附件配置类型，为 B 的发布校验器增加扩展配置规则。验证字段编码、附件模板绑定、适用节点和生效配置不可原地修改。不得复制 C 的 DTO/Repository，不保存附件，不调用文件存储 SPI。”

测试与完成条件：

- C 的配置为空时，纯图定义仍可按正式规则校验；
- 重复表单字段、重复附件绑定、未知适用节点和生效配置原地修改分别有失败测试；
- C 的读取接口异常不得被当作“配置为空”而放行发布；
- 执行模块测试并完成子 agent 审查后提交 B1.5。

建议提交：`feat: validate definition extension configuration`

### B1.6：实现运行时定义快照加载与缓存

实现线程安全的运行时快照加载器和内存缓存。缓存键必须包含定义 ID 与版本；只有已发布且激活、并已通过发布校验的定义才能进入运行时缓存。

缓存规则：

- 未命中时通过 B1.1 端口加载完整数据，并用 B1.2 解析；
- 草稿、未发布、未激活或校验失败的定义不得缓存；
- 加载异常不得缓存空值或半成品；
- 同一键返回稳定快照，不暴露可修改集合；
- A 完成保存、发布、激活、停用、归档或删除事务后，按定义 ID 失效所有相关版本；
- 缓存失效必须在 A 的数据库事务成功提交后发生，回滚事务不得清除当前有效快照；
- M1 不引入第三方分布式缓存，优先使用 Java 8 线程安全内存结构和清晰端口。

提示词：

“实现 Java 8 线程安全的运行时定义快照加载器与内存缓存，键为 definitionId + version。只缓存正式状态为已发布且激活、并已通过校验的不可变快照。提供按 definitionId 失效全部版本的接口，供 A 在事务提交后调用。不得缓存异常、空值、草稿或未激活定义，不引入 Redis/Caffeine 等新依赖。”

测试与完成条件：

- 首次加载访问端口，重复加载命中缓存；
- 不同版本使用不同键；按定义 ID 失效后重新加载；
- 未发布、未激活、校验失败和加载异常均不进入缓存；
- 并发加载同一键不产生可见的可变半成品；
- 执行模块测试并完成子 agent 审查后提交 B1.6。

建议提交：`feat: cache runtime definition snapshots`

### B1.7：A/B/C 联合测试与 M1 收口

在 A/C 的 M1 代码合入 `develop` 后，B 从最新 `develop` rebase，使用真实类型和适配实现完成联合测试。不得保留测试替代接口或兼容别名。

联合测试至少覆盖：

1. 保存一份包含开始、两个用户任务、结束节点的流程图；节点具备坐标和顺序，连线具备顺序；
2. 从 A 的读取能力加载完整图，B 解析后的节点/连线、坐标和顺序与持久化数据一致；
3. 合法图发布校验通过，明显错误图返回完整校验问题；
4. C 的表单字段和附件配置参与校验；
5. 定义发布并激活后可进入缓存；停用、归档、删除或保存新版本后旧缓存按约定失效；
6. 运行时加载拒绝未发布或未激活的定义。

提示词：

“将 B 的图解析、发布校验和运行时缓存与 A 的定义读取/状态类型、C 的表单/附件配置读取能力对齐。删除所有测试替代生产类型，补充 SQLite 或现有持久化实现的联合测试。不得修改 A/C 的职责边界或创建兼容别名。”

测试与完成条件：

- 先执行 `mvn -q -pl platform/platform-core -am test`；
- rebase 与跨模块对齐完成后执行根目录 `mvn -q test`；
- 子 agent 审查重点：重复类型、事务后失效时机、缓存状态门禁、图字段完整性和测试是否真正使用 A/C 实现；
- 两项 Maven 命令和审查均通过后提交 B1.7。

建议提交：`test: verify M1 definition runtime integration`

## 测试夹具矩阵

测试夹具使用业务无关的流程编码和节点名称，不在平台生产代码或通用测试中写入具体业务判断。

| 夹具 | 结构 | 预期 |
| --- | --- | --- |
| 串行合法图 | START → USER_TASK → USER_TASK → END；含坐标、节点/连线顺序 | 校验通过，解析顺序稳定 |
| 缺少开始/结束 | 只有用户任务或只有开始节点 | 返回对应结构问题 |
| 重复编码 | 两节点或两连线编码相同 | 返回唯一性问题 |
| 断裂连线 | 来源或目标节点不存在 | 返回连线完整性问题 |
| 孤立用户任务 | 用户任务无有效入线或出线 | 返回孤立节点问题 |
| 无审批人用户任务 | USER_TASK 无审批人规则 | 返回审批配置问题 |
| 合法条件网关 | 两条以上出线，非默认线有条件，最多一条默认线 | 校验通过 |
| 非法条件网关 | 多默认线、缺少条件或出线不足 | 返回完整网关问题 |
| 合法并行配对 | 分支至少两路，均到达配对汇聚，汇聚唯一出线 | 校验通过 |
| 非法并行配对 | 配对缺失/类型错误/分支不可达/汇聚入线不足 | 返回完整网关问题且遍历有限结束 |
| 扩展配置错误 | 重复表单字段、重复附件绑定或未知适用节点 | 返回 C 扩展校验问题 |
| 缓存状态门禁 | 草稿、未激活、合法激活、停用/归档/删除 | 仅合法激活定义可缓存，变化后正确失效 |

## 验收与合并门禁

- M1 代码基于完成 B0.5 的最新 `develop`，不在旧 M0 分支继续堆叠；
- 流程图快照完整保留节点、连线、坐标、节点顺序、连线顺序及 v4 所需配置；
- 发布校验覆盖需求文档的开始/结束、孤立节点、连线完整性、用户任务审批人配置；
- 发布校验补齐 v4 的条件网关、并行网关、表单字段和附件配置细则；
- 解析结果不可变、排序稳定，图遍历遇到环路能够有限结束；
- 只有已发布且激活的定义可进入运行时缓存；缓存键包含定义 ID 与版本；
- 定义保存、发布、激活、停用、归档、删除成功提交后，旧缓存正确失效；
- 无重复 A/C DTO、枚举、Repository、Service 或 SPI；无 SQLite 专有 SQL、流程实例或任务流转逻辑；
- 每个微任务都有对应测试、Maven 验证、子 agent 审查和独立小提交；
- M1 收口时模块测试与根目录测试均通过，A/B/C 联合测试使用真实实现而非生产替代类型。
