# 实习生 B 技术实现说明

本文件记录已落地的技术契约，避免与实施计划重复。后续 M1～M6 按阶段追加实际实现说明。

## M0：运行时请求契约

### 位置与边界

- 代码包：`com.flowmind.platform.api.request`，位于 `platform-core`。
- 使用 Java 8 JavaBean：公开无参构造及标准 getter/setter；可手写访问器，也可使用 Lombok `@Data`，禁止使用 `record` 或 Java 9+ API。
- M0 不包含流程流转、持久化、SPI、Starter 自动装配、事件或输入校验逻辑。

### 请求继承

```text
OperationRequest
├─ 实例级请求
│  ├─ StartProcessRequest
│  ├─ UpdateVariablesRequest
│  ├─ TerminateProcessRequest
│  ├─ DeleteProcessInstanceRequest
│  ├─ JumpNodeRequest
│  └─ ForceCompleteRequest
└─ TaskOperationRequest
   ├─ SubmitTaskRequest
   ├─ ApproveTaskRequest / RejectTaskRequest / ReturnTaskRequest
   ├─ WithdrawTaskRequest / DirectSendRequest
   ├─ TransferTaskRequest / AddSignRequest
   └─ ClaimTaskRequest / UnclaimTaskRequest / RemindTaskRequest
```

- `OperationRequest`：`operationId`，所有状态修改请求共用。
- `TaskOperationRequest`：继承 `OperationRequest`，增加 `taskId`、`expectedTaskVersion`（`Long`）、`operatorUserId`、`comment`。
- `JumpNodeRequest` 是实例级请求，只含实例 ID 与目标节点等字段，不继承任务基类，也不携带任务版本。

### 关键字段

| 类型 | 已冻结字段 |
| --- | --- |
| `StartProcessRequest` | 流程编码、业务键、实例标题、发起人、发起部门、变量 |
| `UpdateVariablesRequest` | 实例 ID、操作人、变量 |
| `SubmitTaskRequest` | 任务基类字段、变量、`List<AttachmentUploadItem>` |
| 定向动作 | 驳回、直送、跳转使用 `targetNodeCode`；转办使用 `targetUserId`；加签使用 `addSignUserIds` |
| 实例操作 | 终止、删除、跳转、强制办结均包含 `instanceId`；需要操作人/意见的请求显式携带相应字段 |
| `AttachmentUploadItem` | 附件模板编码、归属类型、文件名、内容类型、大小、`byte[] content` |

`AttachmentUploadItem` 位于 `com.flowmind.platform.api.request`，是上传请求的内存载荷，不表示文件存入 SQLite；后续实现须通过文件存储 SPI 保存实际内容。

### 契约测试

- `OperationRequestContractTest` 验证两个请求基类的继承与 JavaBean 属性。
- `RuntimeRequestContractTest` 为全部 17 个修改请求提供有效夹具：统一验证 `operationId`，任务级请求额外验证 `taskId`、`expectedTaskVersion`、`operatorUserId` 和 `comment`。
- 测试覆盖每个请求的专有字段，并独立验证 `AttachmentUploadItem` 的全部六个属性及二进制内容。
- 验证命令：`mvn -q -pl platform/platform-core -am test`。

### 夹具汇总与覆盖门禁（B0.4）

- `RuntimeRequestContractTest` 以 17 个计划内运行时修改请求的类型集合为清单，并与参数化夹具的类型集合比较；集合不一致或出现重复夹具时测试失败。
- 每个请求夹具都需提供非空 `operationId`；任务级夹具还需提供 `taskId`、`expectedTaskVersion` 和 `operatorUserId`。`JumpNodeRequest` 单独断言不继承 `TaskOperationRequest`。
- `RuntimeResultContractTest` 保持对 `TaskActionResult.archivedTasks`、`createdTasks` 和 `replayed` 的验证。测试只验证 DTO 可表达性，不引入运行时幂等、版本校验或流程执行逻辑。

### 运行时结果 DTO（B0.3）

- 代码包：`com.flowmind.platform.api.dto`，同样采用 Java 8 JavaBean。
- `ProcessInstanceDTO` 表达实例标识、定义与流程信息、发起信息、当前节点、变量、起止时间和创建出的 `TaskDTO` 列表。
- `TaskDTO` 表达节点、候选人、受理人、委托人、任务组/分支、`taskVersion` 及时间字段；`HistoryTaskDTO` 表达归档任务、操作关联、变量快照、意见和完成时间。
- `TaskActionResult` 聚合 `operationId`、实例、归档/新建任务及重放标识；`OperationResult` 表达操作号、目标 ID、删除和重放标识。
- `RuntimeResultContractTest` 覆盖上述 DTO 的 JavaBean 属性、任务版本、任务归档/创建关系与操作结果标识；附件上传项由 `RuntimeRequestContractTest` 独立覆盖。
- 实例/任务状态、历史任务的处理类型与动作类型、`OperationResult.targetType` 保留到 C 的正式枚举契约合入后对齐；M0 不使用 `String` 临时枚举值。

### 与 A 的模型及乐观锁契约对齐（B0.5 部分完成）

- 本地 `feature/m0-b-dto-contract` 已快进到 `origin/develop@02eb390`，当前基线包含 A/B 代码，不包含 C 的共享枚举、事件、SPI 或 Starter Service 接口。
- `process_active_task` 仅通过 `definition_id` 关联具体流程定义，不重复保存定义版本；SQLite Schema、`ProcessActiveTaskEntity` 和 `TaskDTO` 均不包含 `version`。实例自身仍通过 `process_instance.version` 和 `ProcessInstanceDTO.version` 保存启动时的定义版本快照。
- `TaskDTO.taskVersion` 为 `Long`，对应 `ProcessActiveTaskEntity.lockVersion`；任务级请求通过同为 `Long` 的 `TaskOperationRequest.expectedTaskVersion` 原样回传该值。
- `RuntimeResultContractTest` 通过反射冻结 `ProcessInstanceDTO.version`、`TaskDTO.taskVersion`、`HistoryTaskDTO.operationId/comment` 与 A 持久化实体及任务请求的对应字段类型，同时继续以真实 setter/getter 调用验证 Lombok 生成的 JavaBean 契约。
- `FlowPlatformSchemaTest.activeTaskReferencesDefinitionWithoutDuplicatingItsVersion` 使用 `PRAGMA table_info(process_active_task)` 正向断言 `definition_id/lock_version`、反向断言不存在 `version`；Repository 集成测试按删除后的六列活动任务结构插入数据。
- 已执行 `mvn -q -pl platform/platform-core -am test` 和根目录 `mvn -q test`，共 101 项测试通过；子 agent 复审未发现阻断问题。
- `001_init_flow_platform.sql` 使用 `CREATE TABLE IF NOT EXISTS`，已由旧脚本创建的本地 SQLite 库不会自动删除原列；M0 未引入迁移框架，需要重建旧本地库后再验证新结构。
- 待 C 合入后再补正式枚举字段，核对 `WorkflowEvent` 对任务/历史 DTO 的复用，完成 SPI/Starter 编译和幂等夹具联合测试；在此之前 B0.5 不标记为全部完成。

### 已知阶段边界

- M0 的夹具只证明 DTO 可表达有效请求，不代替运行时非空、权限、幂等或乐观锁校验。
- 运行时校验、幂等执行、任务状态变更、附件 SPI 调用和数据库操作留待后续阶段实现。
