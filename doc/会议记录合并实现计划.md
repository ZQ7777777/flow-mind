# 会议记录合并实现计划

## 1. 文档目的

本文合并两版会议记录，并结合当前 `platform`、`business-base`、`agent-web` 已实现功能，整理后续实现计划和三人参考分工。

核心目标是：在现有三段式架构上补齐业务办理大厅、流程入口配置、审批详情体验、Agent 参考 skill 和生成模块发布策略，避免重复建设已经由通用基座和流程引擎提供的能力。

## 2. 合并后的会议结论

### 2.1 业务办理入口

- 建设业务办理大厅，但大厅只以图标入口形式展示每个流程定义的录入页入口。
- 每个流程定义绑定一个前端页面超链接，图标和流程名称共同作为入口，点击图标即可进入该流程定义对应的业务录入页/申请页面，例如入金申请页面。
- 入口图标、展示名称和页面超链接不应长期硬编码在前端侧边栏中，应由业务配置管理页面配置。
- 业务大厅不展示待办、审批、轨迹或流程办理状态，这些仍由通用流程页面承载。
- 业务配置管理需要同时支持手工配置流程定义入口和 Agent/VibeCoding 生成的表单录入页入口。

### 2.2 详情页展示方式

- 流程详情页应重点展示业务信息和办理动作。
- 流程图、流程轨迹、审批意见不直接铺开显示，改为按钮打开弹窗。
- 流程图不作为首屏核心内容，业务字段、附件、当前节点和可办理动作优先。

### 2.3 模块解耦与重启策略

- 新增业务模块应与原有业务系统解耦。
- 前端生成业务页也应作为单独模块接入。
- Agent 生成部分支持开发期热加载或快速重载。
- 生产/测试环境首期不做运行时插件热加载；Agent 只生成前端表单区域后，原则上不因新增业务重启业务后端。
- 只改前端生成页面或表单区域时，只需重新构建/发布前端。

### 2.4 接口边界

- 上传、提交、审批等运行期能力应使用流程引擎已有能力，并由 `business-base` 通用后端统一封装。
- Agent 只生成涉及表单字段的前端：业务发起页的表单区域，以及审批页中需要随节点变化展示或编辑的表单区域。
- 业务发起、审批提交、附件处理、流程变量保存最终由通用后端调用流程引擎能力完成。
- 后续审批、附件、流程轨迹、审批意见、任务动作统一走 `business-base` 通用接口。
- 入金申请单需要明确前端表单页面/区域、通用业务接口、VibeCoding/Agent 生成输入输出定义。

### 2.5 表单字段和审批人配置

- 审批人配置应整理成清晰字段，避免只依赖原始 JSON。
- 流程定义阶段可新增、修改表单字段。
- 审批过程中可在受控节点修改已有流程变量，例如退回到申请节点后补充或修改字段。
- 运行中新增流程定义字段应通过新流程定义版本处理，不直接破坏历史实例。

### 2.6 Agent 参考 skill 与模板

- 需要整理一份 Agent 生成业务模块的参考 skill。
- skill 应告诉业务 Agent 如何生成需求文档、如何生成业务发起页表单区域、如何生成审批页表单区域，以及如何遵守通用审批区边界。
- 模板 skill 需要说明不同节点下表单字段区域的展示和编辑方式；审批按钮、意见、流转动作仍由通用组件提供。
- 业务 Agent 与用户对话后，应先生成需求文档，明确业务字段、附件、节点、审批人规则和需要调用的接口，再进入代码生成。

## 3. 当前已实现功能基线

### 3.1 平台能力

`platform` 已提供流程定义、流程实例、任务流转、附件、轨迹、意见、审批动作、幂等和版本控制等流程引擎能力。

后续实现不应在业务系统中重写流程引擎，只需要通过 `platform-starter` 或业务侧封装接口调用这些能力。

### 3.2 Business Base 通用业务基座

`business-base` 当前已经具备：

- 登录与业务系统应用壳。
- 生成业务路由接入点。
- 我的待办、我的已办、我发起的、我的已阅列表。
- 通用流程详情页。
- 通用业务字段展示和部分受控编辑。
- 通用附件上传、替换、下载、删除。
- 通用审批动作：通过、提交、驳回、退回、撤回、直送、转办、委托、加签、认领、取消认领、催办。
- 管理员流程定义页面，支持流程图、节点、连线、表单字段、附件配置和审批人规则配置。

### 3.3 Agent Web 生成能力

`agent-web` 当前已经具备：

- 需求对话和结构化需求采集。
- 流程定义创建、发布、激活。
- 当前入金申请样例已生成业务发起 Controller、Service、DTO、Vue 页面、前端 API、路由和测试；后续目标口径收缩为只生成表单字段相关前端。
- 目标工程契约校验和生成白名单。
- 现有入金申请生成样例。

### 3.4 当前主要缺口

- 业务办理大厅还没有按流程定义展示的录入页图标入口。
- 流程定义与前端页面地址还没有可配置绑定关系。
- 入金申请录入页入口目前通过生成路由直接进入，尚未通过业务大厅配置进入。
- 流程图、轨迹、审批意见当前在详情页直接展示，还未改为按钮弹窗。
- Agent 生成规则还散落在 prompt 和契约中，缺少可复用参考 skill。
- 生成后的发布/重启策略需要在系统和文档中显式化。

## 4. 目标方案

### 4.1 总体边界

继续保持三段式边界：

| 模块 | 职责 |
|---|---|
| `platform` | 流程定义、实例、任务、附件、轨迹、审批动作等流程引擎能力 |
| `agent-web` | 需求对话、流程定义落地、表单字段前端生成、质量验证 |
| `business-base` | 最终业务系统运行入口、业务大厅、通用待办/详情/审批/附件、生成业务页面承载 |

### 4.2 业务大厅方案

新增业务大厅页面，建议路由为：

```text
/business-hall
```

业务大厅只展示流程定义录入页图标入口，建议采用宫格或紧凑卡片形式。每个入口保持最小信息：

- 流程定义 ID 或流程编码
- 流程名称
- 入口图标
- 录入页超链接
- 操作：点击图标进入业务录入页/申请页面

业务大厅不展示待办、审批、流程轨迹、审批意见、流程实例状态等办理信息。

后端建议新增或扩展接口：

```text
GET /api/workflow/process-entry-links
GET /api/workflow/process-entry-links/{definitionId}
```

当前已有的：

```text
GET /api/workflow/startable-processes/entry-application
```

可作为兼容接口保留，但业务大厅应使用新的流程定义录入页图标入口数据接口。

### 4.3 流程入口配置方案

在流程定义管理中增加业务入口配置，首期建议字段：

| 字段 | 说明 |
|---|---|
| definitionId | 流程定义 ID，入口绑定到具体流程定义 |
| processCode | 流程编码 |
| processName | 流程名称 |
| entryDisplayName | 业务大厅图标下方展示名称，默认可使用流程名称 |
| `entryPageUrl` | 前端录入页地址，例如 `/generated/entry-application/apply` |
| `entryIcon` | 业务大厅展示图标，例如 `wallet`、`file-plus`、`receipt` |
| `entryIconColor` | 图标主题色，可选，用于区分不同业务入口 |
| `entrySource` | `MANUAL` 或 `AGENT_GENERATED` |
| `enabled` | 是否在业务大厅展示该流程定义的录入页入口 |
| `remark` | 备注 |

存储方案有两种：

1. 首期推荐：新增业务侧入口配置表，由 `business-base` 管理，不污染流程引擎核心定义。
2. 后续可选：将入口地址作为流程定义扩展元数据纳入平台定义模型。

首期建议选择第一种，便于保持 `platform` 业务无关。

### 4.4 详情页按钮弹窗方案

调整 `WorkflowDetailView` 的页面布局：

- 主视图保留：实例摘要、业务信息、附件、办理动作。
- 顶部或业务信息区右侧增加按钮：
  - 查看流程图
  - 查看流程轨迹
  - 查看审批意见
- 点击按钮后打开弹窗，复用现有组件：
  - `ProcessGraph`
  - `ProcessTimeline`
  - `CommentPanel`

弹窗内支持滚动和关闭，不改变现有后端详情 DTO。

### 4.5 生成模块解耦方案

后续目标生成目录收缩为前端表单相关产物：

```text
business-base/frontend/src/modules/generated/**
business-base/frontend/src/api/generated/**
business-base/frontend/src/router/generated-routes.ts
```

当前已有后端生成目录作为历史兼容保留，不作为后续新增业务的默认生成范围：

```text
business-base/backend/src/main/java/com/flowmind/business/generated/**
business-base/backend/src/test/java/com/flowmind/business/generated/**
```

生成模块边界：

- Agent 只生成发起页表单字段区域，以及审批页中与表单字段展示/编辑相关的局部区域。
- 页面壳、导航、提交按钮、审批按钮、意见、附件、轨迹、流程图由 `business-base` 通用前端提供。
- 发起提交、审批提交、变量保存、附件处理由 `business-base` 通用后端提供。
- 生成路由只登记业务发起入口；审批页不按业务生成整页。
- 生成代码不得修改通用待办、详情、审批、附件组件。
- 生成代码不得生成后端 Controller、Service、DTO、业务表、Repository、Mapper、DAO 或流程引擎逻辑。

### 4.6 发布和重启策略

首期采用构建时集成：

| 变更类型 | 处理方式 |
|---|---|
| 只改前端表单区域或发起页 | 重新构建/发布前端 |
| 新增业务入口配置 | 不需要重启后端，只需保存配置并刷新业务大厅 |
| 通用后端接口变更 | 重新构建并重启 `business-base` 后端 |
| 修改通用 API 契约 | 前后端一起验证、构建和发布 |
| 本地开发 | 前端使用 Vite HMR，后端仅在通用接口变化时快速重启 |
| 生产/测试 | 前端生成产物按前端发布流程上线；后端仅在通用能力变更时重启 |

首期不做后端生成模块热加载。因为 Agent 默认不再生成后端代码，新增业务通常只影响前端表单区域和业务入口配置；只有通用后端能力变化时才需要后端发布。

### 4.7 表单字段和审批字段规则

定义期：

- 表单字段、附件、审批人规则在流程定义管理页面配置。
- 审批人配置应从纯 JSON 输入逐步升级为结构化控件。
- 已发布/激活流程的字段变更应通过复制新版本或新定义处理。

运行期：

- 允许在退回申请节点、直送等受控场景修改已有流程变量。
- 不允许普通审批节点任意新增未知变量。
- 不允许历史实例因新字段配置被破坏。
- 表单字段展示根据实例绑定的定义版本渲染。

## 5. Agent 参考 skill 建设

建议新增一份业务生成参考 skill，名称可为：

```text
flowmind-business-generation
```

skill 内容应覆盖：

### 5.1 需求对话

Agent 需要与用户确认：

- 业务编码和业务名称。
- 业务目标。
- 参与角色。
- 表单字段、字段类型、控件类型、必填和校验规则。
- 附件编码、名称、格式、大小、数量、适用节点。
- 流程节点、节点顺序、分支条件。
- 审批人规则。
- 多人办理方式。
- 退回、驳回、直送、催办、超时等运行规则。
- 业务发起页标题和入口名称。

### 5.2 需求文档输出

进入代码生成前，Agent 应生成需求文档，至少包含：

- 业务概述。
- 流程范围。
- 角色与权限。
- 表单字段清单。
- 附件清单。
- 流程节点和流转规则。
- 审批人配置。
- 需要调用的接口。
- 生成文件清单。
- 验收用例。

### 5.3 代码生成边界

skill 必须明确：

- 只能生成和表单字段有关的前端产物：发起页表单区域、审批页表单展示/编辑区域。
- 后续审批按钮、意见、附件、轨迹、流程图全部使用通用审批区和通用详情能力。
- 发起提交和审批提交由通用后端接口处理，Agent 不生成提交 Controller 或 Service。
- 不生成流程引擎逻辑。
- 不生成业务数据库表。
- 不修改通用业务大厅、通用审批详情、通用附件组件。

### 5.4 审批区模板说明

skill 应告诉 Agent：

- 不同节点的审批动作区由通用组件根据 `allowedActions`、当前任务版本、驳回目标、候选用户等信息展示。
- Agent 不生成审批按钮、审批意见框、流转动作或整张审批页。
- Agent 可生成审批页中的表单字段局部区域，用于不同节点的字段只读、可编辑、隐藏或强调展示。
- 申请节点被退回时，通用详情页加载对应表单字段区域并启用允许编辑的业务字段。
- 审批意见、流程轨迹、流程图由按钮弹窗查看。

## 6. 实施步骤

### P1：业务入口配置

- 新增业务入口配置模型。
- 新增业务入口配置后端接口。
- 在流程定义管理页面增加入口地址、入口图标和展示名称配置。
- 支持将 Agent 生成的前端表单录入页路由绑定到具体流程定义。
- 保留入金申请现有录入页入口作为迁移样例。

退出条件：

- 管理员可为每个流程定义配置录入页页面地址和业务大厅入口图标。
- 配置启用后，业务大厅只以图标形式展示该流程定义的录入页入口。
- 点击图标能进入对应业务录入页/申请页面。

### P2：业务大厅页面

- 新增业务大厅前端页面。
- 侧边栏增加“业务大厅”入口。
- 以图标宫格展示多个已配置流程定义的录入页入口。
- 根据入口地址是否有效决定图标入口是否可点击；流程状态信息不在大厅展开展示。
- 对无入口地址或无权限情况给出清晰提示。

退出条件：

- 入金申请录入页通过业务大厅图标入口进入。
- 后续新增流程定义只需绑定录入页地址，无需修改侧边栏。

### P3：详情页弹窗化

- 在详情页增加“查看流程图”“查看流程轨迹”“查看审批意见”按钮。
- 将现有流程图、轨迹、意见组件移入弹窗。
- 主页面优先展示业务信息、附件和办理动作。
- 补充移动端弹窗适配。

退出条件：

- 默认详情页不直接展开流程图、轨迹、审批意见。
- 三类弹窗均可打开、关闭、滚动查看。
- 现有详情数据接口不需要改变。

### P4：生成模块发布策略显式化

- 在 Agent 生成完成页展示受影响范围：默认前端表单区域。
- 给出本地前端热更新/重新构建提示和生产前端发布提示。
- 在生成质量报告中明确“本次不涉及后端重启”；只有通用后端能力变更时才提示后端重启。
- 文档化不同变更类型对应的发布动作。

退出条件：

- 用户能清楚知道生成后通常只需要刷新或发布前端。
- 不再把“前端热更新”误解为后端运行时插件热加载。

### P5：Agent 参考 skill 和需求文档

- 新增或整理 `flowmind-business-generation` skill。
- 将当前生成 prompt 中稳定规则沉淀到 skill。
- 在 Agent 对话确认后生成需求文档。
- 需求文档中明确通用接口调用、前端表单区域和生成文件清单。
- 将 skill 与现有生成契约、目标工程白名单对齐。

退出条件：

- Agent 能先产出需求文档，再进入生成。
- 文档中明确入金申请单前端表单区域、通用业务接口和 VibeCoding/Agent 接口。
- 生成文件仍只落在前端表单相关白名单目录。

### P6：审批字段和表单字段完善

- 将审批人配置控件进一步结构化，减少手写 JSON。
- 明确各审批人规则字段含义。
- 梳理退回申请节点时的字段编辑体验。
- 增加运行期变量编辑校验和测试。

退出条件：

- 流程配置人员能通过字段控件配置审批人。
- 退回后申请人可修改允许修改的业务字段。
- 普通审批节点不能随意新增未知字段。

## 7. 三人参考分工

### A：Agent 生成与参考 skill

主责：

- 编写 Agent 参考 skill。
- 整理需求文档模板。
- 明确 VibeCoding/Agent 需要使用的通用接口和前端插槽/组件契约。
- 调整生成提示词和生成质量检查。
- 保证生成模块仍遵守白名单和运行边界。

建议任务：

1. 编写 `flowmind-business-generation` skill。
2. 将需求文档模板接入需求确认流程。
3. 在生成报告中输出页面地址、前端表单区域文件清单、通用接口说明和发布提示。
4. 增加 Agent 侧测试，覆盖需求文档、skill 约束、生成路由保持。

交付物：

- Agent 参考 skill。
- 需求文档模板。
- 入金申请样例需求文档。
- Agent 前端表单生成契约说明。

### B：后端与流程配置

主责：

- 业务大厅后端接口。
- 流程定义与页面入口绑定。
- 业务入口配置存储。
- 通用接口边界和权限。
- 发布/重启策略说明。

建议任务：

1. 新增业务入口配置表或业务侧配置模型。
2. 新增 `/api/workflow/process-entry-links` 流程定义录入页图标入口数据接口。
3. 扩展管理员配置接口，支持保存入口页面地址。
4. 保证入口数据只返回当前用户可访问且已配置录入页地址的流程定义图标入口。

### 8.3 后端提供给 Agent 的接口契约

后端需要告诉 Agent 的不是 `platform` 内部接口，也不是每个业务单独生成的 Controller 或 Service，而是 `business-base` 暴露的一组稳定通用接口。Agent 生成代码时只能调用这些通用接口，不直接调用流程引擎，不生成业务后端提交接口。

#### 8.3.1 发起页运行时接口

Agent 生成的业务发起页在用户填写表单、上传附件并点击提交时，调用以下接口：

```text
GET  /api/workflow/processes/{processCode}/start-context
POST /api/workflow/processes/{processCode}/start-submit
```

| 接口 | 调用方 | 作用 |
|---|---|---|
| `GET /api/workflow/processes/{processCode}/start-context` | Agent 生成的发起页 | 获取当前流程发起所需的上下文，包括流程定义版本、表单字段规则、附件规则、默认值、当前用户是否可发起、不可发起原因等。Agent 用这些元数据渲染表单和做前端即时校验。 |
| `POST /api/workflow/processes/{processCode}/start-submit` | Agent 生成的发起页 | 用户点击提交时调用。后端接收表单变量和发起附件，从登录态识别当前用户，校验字段、附件、权限和定义版本，然后调用流程引擎启动并提交流程。 |

`POST /api/workflow/processes/{processCode}/start-submit` 是所有 Agent 生成发起页共用的提交接口，用来替代每个业务单独生成的接口，例如历史兼容接口 `POST /api/generated/entry-application/submit`。后续新增业务不再由 Agent 生成业务专用提交 Controller、Service 或 DTO。

#### 8.3.2 审批页字段区域接口

Agent 不生成整张审批页，只生成审批页中与业务字段展示或受控编辑有关的局部区域。该区域需要通过通用详情接口获取当前任务或实例的数据：

```text
GET  /api/workflow/tasks/{taskId}
GET  /api/workflow/instances/{instanceId}
POST /api/workflow/tasks/{taskId}/submit
POST /api/workflow/tasks/{taskId}/approve
```

| 接口 | 调用方 | 作用 |
|---|---|---|
| `GET /api/workflow/tasks/{taskId}` | 通用详情页、Agent 生成的审批字段区域 | 获取当前待办任务详情，包括实例信息、业务变量、表单字段、当前节点、任务版本、可办理动作、附件、字段可见/只读/可编辑/必填规则。Agent 用它判断当前节点下字段如何展示或编辑。 |
| `GET /api/workflow/instances/{instanceId}` | 通用详情页、Agent 生成的只读字段区域 | 获取流程实例详情，用于已办、我发起的、详情查看等只读场景。Agent 用返回的变量和字段定义展示业务信息。 |
| `POST /api/workflow/tasks/{taskId}/submit` | 通用审批区或退回申请节点的表单区域 | 退回到申请节点后，申请人修改允许编辑的字段并重新提交。后端校验当前节点允许提交的变量和附件。 |
| `POST /api/workflow/tasks/{taskId}/approve` | 通用审批动作区 | 审批通过。首期可只由通用审批动作区调用；如果后续允许审批节点同时修改受控业务字段，可扩展为携带 `variables`，后端仍需校验字段权限。 |

通过、驳回、退回、撤回、直送、转办、委托、加签、认领、取消认领、催办等审批动作接口已经由通用审批动作区承载。Agent 可以知道这些接口存在，但不应在业务生成页里重复生成审批按钮、意见框或流转动作逻辑。

#### 8.3.3 附件接口

Agent 生成页面可以根据附件配置生成上传、替换、下载、删除控件，但附件处理统一调用通用接口：

```text
GET    /api/workflow/attachments
POST   /api/workflow/instances/{instanceId}/attachments
POST   /api/workflow/tasks/{taskId}/attachments
PUT    /api/workflow/tasks/{taskId}/instance-attachments/{attachmentId}
GET    /api/workflow/attachments/{attachmentId}/content
DELETE /api/workflow/attachments/{attachmentId}
```

| 接口 | 作用 |
|---|---|
| `GET /api/workflow/attachments` | 查询实例或任务下的附件列表。 |
| `POST /api/workflow/instances/{instanceId}/attachments` | 上传实例级附件。 |
| `POST /api/workflow/tasks/{taskId}/attachments` | 上传任务级附件。 |
| `PUT /api/workflow/tasks/{taskId}/instance-attachments/{attachmentId}` | 在任务办理过程中替换已有实例附件。 |
| `GET /api/workflow/attachments/{attachmentId}/content` | 下载附件内容。 |
| `DELETE /api/workflow/attachments/{attachmentId}` | 删除附件。 |

发起时随表单一起提交的附件应由 `POST /api/workflow/processes/{processCode}/start-submit` 原子处理，避免先创建流程实例再补传附件导致半成品实例。

#### 8.3.4 业务大厅入口接口

业务大厅和生成后的业务入口展示使用以下接口：

```text
GET /api/workflow/process-entry-links
GET /api/workflow/process-entry-links/{definitionId}
```

| 接口 | 调用方 | 作用 |
|---|---|---|
| `GET /api/workflow/process-entry-links` | 业务大厅页面 | 查询当前用户可访问、已启用且已绑定录入页地址的流程入口，用于展示图标、名称和跳转地址。 |
| `GET /api/workflow/process-entry-links/{definitionId}` | 业务大厅页面、Agent 生成页可选 | 查询某个流程定义的入口绑定信息，包括入口展示名称、图标、颜色、录入页地址、来源和启用状态。 |

当前已有 `GET /api/workflow/startable-processes/entry-application` 只作为入金申请兼容接口保留，不作为业务大厅和后续 Agent 生成业务的默认入口接口。

#### 8.3.5 Agent 生成发布阶段接口

Agent Web 在生成前端表单页并完成质量校验后，需要把生成页面登记到业务系统，供业务大厅展示：

```text
PUT /api/admin/business-entry-configs/by-definition/{definitionId}
```

| 接口 | 调用方 | 作用 |
|---|---|---|
| `PUT /api/admin/business-entry-configs/by-definition/{definitionId}` | Agent Web、管理端 | 将某个流程定义与 Agent 生成的前端录入页地址绑定起来，例如把流程定义 `definitionId` 绑定到 `/generated/entry-application/apply`。该接口应设计为幂等 upsert，支持 Agent 重试，不生成重复配置。 |

建议 Agent Web 提交以下字段：

```json
{
  "entryDisplayName": "入金申请",
  "entryPageUrl": "/generated/entry-application/apply",
  "entryIcon": "wallet",
  "entryIconColor": "#1677ff",
  "entrySource": "AGENT_GENERATED",
  "enabled": false,
  "generationId": "可选，生成批次 ID",
  "artifactRevision": "可选，生成产物版本"
}
```

首期建议生成完成后默认 `enabled=false`，前端构建或发布成功后再启用入口，避免业务大厅出现不可访问页面。

#### 8.3.6 校验规则暴露方式

表单和附件校验不需要作为单独校验方法暴露给 Agent。后端应通过 `start-context` 和 `tasks/{taskId}` 返回字段、附件和节点权限元数据，Agent 根据这些规则做前端即时提示；最终权威校验仍在后端提交接口内部执行。

后端返回给 Agent 的规则元数据建议包括：

| 类型 | 建议字段 |
|---|---|
| 表单字段 | `fieldCode`、`fieldName`、`fieldType`、`controlType`、`required`、`visible`、`editable`、`defaultValue`、`validationRule`、`options`、`sortOrder` |
| 附件配置 | `attachmentCode`、`attachmentName`、`required`、`minCount`、`maxCount`、`allowedExtensions`、`maxSizeMb`、`uploadable`、`replaceable`、`deletable` |
| 流程上下文 | `definitionId`、`processCode`、`processName`、`definitionVersion`、`currentNodeCode`、`taskId`、`expectedTaskVersion`、`startable`、`disabledReason` |

后端提交接口必须再次校验字段是否属于当前流程定义、字段当前节点是否允许编辑、必填和类型是否合法、附件规则是否满足、用户是否有权限、定义版本或任务版本是否匹配。Agent 生成的前端校验只用于提升填写体验，不能作为最终可信依据。

## 9. 验收标准

- 业务大厅以图标形式展示多个流程定义的录入页入口。
- 入金申请录入页可以通过业务大厅图标入口进入，不依赖侧边栏硬编码。
- 流程定义管理可以为每个流程定义配置对应的前端录入页地址、入口图标和展示名称。
- Agent 生成新的前端表单录入页后，只需绑定到流程定义即可在业务大厅出现。
- 流程图、流程轨迹、审批意见默认不直接铺开，均通过按钮弹窗查看。
- 通用审批动作、附件上传下载、流程变量展示不回归。
- Agent 不生成业务后端；发起和审批提交由通用后端调用流程引擎。
- 生成模块仍只写入前端表单相关白名单目录。
- 需求文档能明确业务字段、附件、节点、审批人规则、接口和验收用例。
- 文档中清楚说明本地开发热加载和生产重启边界。

## 10. 风险与注意事项

- 不要把入口页面地址直接硬编码进流程定义列表页面。
- 不要让前端直接调用 `platform` 独立调试接口。
- 不要在生成代码中复制通用审批、附件、轨迹逻辑。
- 不要把运行时插件热加载作为首期目标。
- 不要在历史流程实例上直接套用新字段定义，避免历史数据展示错乱。
- 入口配置需要做权限控制，普通用户不能修改流程入口。
- 外部 URL 如需支持，必须单独评估跳转安全和白名单。

## 11. 推荐实施顺序

1. 先做业务入口配置后端和业务大厅页面。
2. 再把入金申请入口迁移到业务大厅。
3. 然后改详情页弹窗体验。
4. 同步整理 Agent 参考 skill 和需求文档模板。
5. 最后完善审批字段结构化配置和发布/重启提示。

这样可以先打通“流程定义到录入页图标入口”的主链路，再优化详情体验和 Agent 生成规范，风险最小，也最容易分工并行。
